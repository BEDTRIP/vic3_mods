### E&F Hotfix — сколько local_currency оставляем стране
###
### E&F выдавал стране без денежной системы плоские 2500 local_currency на
### КАЖДЫЙ штат. Эта выдача отключена в источнике
### (static_modifiers/zz_ef_no_money_production.txt), а взамен страна
### получает столько, сколько насчитано здесь: по населению, среднему
### уровню жизни и таблице потребностей E&F. Считаем по стране целиком
### и делим между штатами.
###
### Кому это применяется — см. common/scripted_triggers/.
###
########################################################################
### Почему модификатор страновой
###
### Проверено запуском: multiplier в add_modifier вычисляется НЕ в том
### скоупе, где стоит эффект. Внутри every_scope_state триггеры видят штат
### нормально, а множитель строкой ниже — нет:
###
###   Value of wrong type in 'zz_ef_local_currency_on_actions.txt:39'.
###   Got value of type 'none'
###
### Поэтому модификатор вешается на страну, а разделение по штатам — просто
### деление на их число. Побочный эффект: штаты одной страны получают
### поровну, хотя у Черкессии они 590 тыс и 74 тыс населения. Лечится только
### отказом от модификаторов в пользу зданий — этим занимается мод банков.
###
########################################################################
### Почему НЕ по фактическому потреблению
###
### Пробовали читать state_goods_consumption по товару local_currency и
### подгонять выпуск под него. Технически это работает: сумма по штатам
### собирается внутри странового script value и остаётся страновым числом
### (так устроен ванильный country_total_urbanization). Но по смыслу — нет.
###
### В залитом рынке потребление измеряет не потребность, а доступность.
### Валюты много и она дешёвая -> попы охотно ей закрывают popneed_currency
### -> потребление большое -> мы разрешаем печатать много -> валюты
### становится ещё больше. Ионические острова на британском рынке (188 тыс
### населения, расчётных ~113 единиц) так печатали полные 2500.
###
### Потолок в 2x от расчёта самораскрутку убрал, но получилось то же самое
### в мягкой форме: в этот потолок стали упираться все подряд, и у всех
### стабильно выходило вдвое больше расчётного.
###
### Отличить "им правда столько надо" от "им просто дёшево достаётся" по
### потреблению нельзя в принципе. Настоящий спрос (buy_orders) игра считает
### только на уровне рынка, а он общий на всех участников и для одной
### маленькой страны бесполезен. Поэтому — чистый расчёт, без обратной связи.
###
########################################################################
### Откуда взялась кривая
###
### Потребность в валюте задана в common/buy_packages/00_ef_buy_packages.txt:
### E&F дописывает popneed_currency во все 99 уровней достатка. Вот она,
### в фунтах на уровень:
###
###    1 -> 21     10 -> 37     20 -> 40     30 ->  62     40 ->  96
###    5 -> 28     15 -> 41     25 -> 46     35 ->  76     99 -> 6177
###
### Форма несимметричная: до 10 уровня растёт бодро, с 10 по 20 стоит на
### месте, после 20 разгоняется, после 40 уходит в экспоненту. Ниже она
### разложена на отрезки — каждый кусок это своя наклонная, суммируются.
###
### Калибровка по трём замерам (потребление страны целиком):
###
###   Новая Гранада  1.47 млн, SoL 7.3 -> 1640
###   Черкессия      664 тыс,  SoL ~11 ->  372
###   Бухара         1.47 млн, SoL 6.1 ->  380
###
### Разброс на душу между ними четырёхкратный, и ни население, ни достаток
### его не объясняют — по кривой все трое должны потреблять почти одинаково.
### Поэтому rate взят как среднее геометрическое трёх подгонок и затем
### подрезан по итогам прогона. При rate = 0.0132 формула даёт:
###
###   Новая Гранада  634 (39% от замера)
###   Черкессия      327 (88%)
###   Бухара         597 (157%)
###
### ЕСЛИ ВАЛЮТЫ ВСЁ ЕЩЁ МНОГО ИЛИ МАЛО — крутить надо rate, он линейный
### и единственный: 0.0132 -> 0.0099 это минус четверть всем и сразу.
########################################################################

### ЕДИНСТВЕННАЯ РУЧКА: единиц валюты на 1000 душ на каждый фунт таблицы
### buy_packages. Линейная: вдвое меньше значение — вдвое меньше валюты.

zz_ef_local_currency_rate = {
	value = 0.0125
}

########################################################################
### Кривая потребности по достатку — кусочно-линейная аппроксимация
### таблицы buy_packages. Каждый отрезок обрезан по своим границам и
### умножен на свой наклон, дальше всё складывается.
###
### Проверка: SoL 6.1 -> 30.8 (таблица 31), SoL 11 -> 37.3 (38),
###           SoL 30 -> 62.0 (62), SoL 40 -> 96.0 (96).
########################################################################

zz_ef_lc_curve_a = {			# 0..10, наклон 1.6
	value = average_sol
	min = 0
	max = 10
	multiply = 1.6
}

zz_ef_lc_curve_b = {			# 10..20, полка
	value = average_sol
	subtract = 10
	min = 0
	max = 10
	multiply = 0.3
}

zz_ef_lc_curve_c = {			# 20..30, разгон
	value = average_sol
	subtract = 20
	min = 0
	max = 10
	multiply = 2.2
}

zz_ef_lc_curve_d = {			# 30..40
	value = average_sol
	subtract = 30
	min = 0
	max = 10
	multiply = 3.4
}

zz_ef_lc_curve_e = {			# выше 40 — грубо, туда почти никто не заходит
	value = average_sol
	subtract = 40
	min = 0
	max = 59
	multiply = 7
}

zz_ef_local_currency_wealth_curve = {
	value = 21
	add = zz_ef_lc_curve_a
	add = zz_ef_lc_curve_b
	add = zz_ef_lc_curve_c
	add = zz_ef_lc_curve_d
	add = zz_ef_lc_curve_e
}

########################################################################
### Собственно расчёт
########################################################################

### Сколько штатов у страны. Модификатор страновой, но действует на каждый
### штат, поэтому страновую потребность надо разделить между ними.
zz_ef_local_currency_state_count = {
	value = 0
	every_scope_state = {
		add = 1
	}
	min = 1
}

### Потребность страны целиком
zz_ef_local_currency_demand = {
	value = total_population
	divide = 1000
	multiply = zz_ef_local_currency_wealth_curve
	multiply = zz_ef_local_currency_rate
}

### Сколько выдаём на штат.
### Модификатор zz_ef_local_currency_fix имеет базу +1, это его множитель.
###
### Ефовские плоские 2500 отключены в источнике через REPLACE, поэтому
### здесь именно выдача, а не вычитание, и верхнего предела в 2500 больше
### нет: крупная страна получит столько, сколько ей насчитано.
### max = 25000 стоит просто предохранителем от абсурда.
zz_ef_local_currency_per_state = {
	value = zz_ef_local_currency_demand
	divide = zz_ef_local_currency_state_count
	min = 25
	max = 25000
}

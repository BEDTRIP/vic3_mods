## 2. Где предварительный анализ Composer оказался неверным

Это важнее самих правок — четыре из семи пунктов его чеклиста были ложными.

### 2.1 Agassiz / silver — патч не нужен вообще (было «❌ сломан, полная переработка»)

```
E&F:  bg_silver_mining = { parent_group = bg_mining ... }
MR:   agassiz_can_find_new_vein_trigger      → is_building_group = bg_mining
      agassiz_mine_valid_for_improvement_trigger → is_building_group = bg_mining
```

`is_building_group` в Vic3 проверяет **всю цепочку родителей**, а не точное совпадение. Доказательство прямо в ванили 1.13
(`common/scripted_effects/00_victoria_scripted_effects.txt:2185`):

```
is_building_group = bg_military # Derives from barracks and naval bases.
```

Казармы — `bg_army`, военно-морские базы — `bg_navy`; обе — дети `bg_military`.

Значит `building_silver_mine` **уже** попадает в новый unified «Improve Mining» и в его GUI-выбор целей без единой строчки компача. То же касается MR-овского `bg_uranium_mining` (тоже child of `bg_mining`).

Уточнение по пер-рудным JE: `je_agassiz_find_coal/iron/lead/sulfur/gold/uranium_project` в MR 2.8.3e **по-прежнему определены** и упоминаются в `agassiz_geologist_project_active_trigger`, но **ни один эффект их больше не выдаёт** — это мёртвое легаси. Реально работают `je_agassiz_improve_mines_project` и `je_agassiz_find_oil_project`.

Старый блок компача при переносе as-is был бы **активно вреден**: его override
`agassiz_geologist_project_with_busy_geologist_active_trigger` не содержит
`je_agassiz_improve_mines_project`, то есть геолог считался бы свободным во время активного проекта.

### 2.2 `buy_packages` — конфликта нет (было «нужен merge-компач или megapack»)

```
E&F: INJECT:wealth_10={goods={popneed_currency=37}}
MR:  TRY_INJECT:wealth_10 = { goods = { popneed_entertainment = 1 } }
```

Оба мода **инжектят**, ни один не переопределяет. 90 «дублирующихся ключей» из отчёта конфликтов — артефакт скана, который сравнивает имена ключей и не смотрит на префикс операции. Обе pop need применяются. Никаких действий не требуется.

### 2.3 `building_railway` — то же самое

E&F `INJECT:`, MR `TRY_INJECT:` → аддитивно. Load order значения не имеет.

### 2.4 Инфляция — пересборка не потребовалась

Тела `inflation_on_consumer_goods` и `inflation_on_raw_material` в E&F 04.07.2026 **побайтово совпадают** с базой в старом компаче (сверено нормализованным diff). Новые корзины (`inflation_on_energy`, `inflation_on_manufactured_goods`, `inflation_on_military_equipment`) MR-товаров не содержат и не трогаются.

Правки — только комментарии в шапке.

### 2.5 Технологии — пересечений нет

E&F `REPLACE:` 10 ванильных tech (`banking`, `currency_standards`, `central_banking`, `mutual_funds`, `corporate_charters`, `investment_banks`, `international_exchange_standards`, `joint_stock_companies`, `postal_savings`, `modern_financial_instruments`). MR патчит 89 других ключей. Пересечение множеств — пустое.

## 3. Что реально изменилось

### 3.1 Список зданий

Morgenröte 2.8.3e — ровно **62** собственных здания (проверено сравнением множеств, расхождений в обе стороны нет).

| | Здания |
|---|---|
| **+6** | `building_andersson_institute`, `building_curie_facility`, `building_curie_reactor`, `building_lepsius_needle`, `building_lepsius_obelisk`, `building_elgar_opera` |
| **−1** | `building_gaudi_sagrada` (удалено из MR) |

Все пять новых Andersson/Curie/Lepsius — `can_build_private = { always = no }`, то есть чисто государственные → только `pmg_market_liquidity`, без stock-PMG. Проверено чтением определений, а не по группе здания.

`building_elgar_opera` уже был в effects, но не имел INJECT stock-PMG — теперь есть (`pmg_private_ownership_manufacture_stock`). Здание приватно-строимое (реальное условие в `can_build_private`, не заглушка).

`INJECT:` заменён на `TRY_INJECT:` — именно из-за случая `gaudi_sagrada`: удаление здания в MR даёт спам в error.log у всех подписчиков.

### 3.2 Private ownership: override → on_action

Старый компач переопределял `financial_center_ef_on_yearly_pulse_country`. Два минуса:

1. Override надо держать синхронным с E&F вручную.
2. **E&F вызывает этот эффект только под условием** `has_modifier = has_financial_center` (`common/on_actions/00_ef_on_action.txt:192`). То есть MR-здания не переключали stock-PM ни в одной стране без финцентра — это был баг компача.

Теперь `mr_private_ownership_production_stocks` вызывается из собственного файла
`common/on_actions/zz_ef_mr_on_actions.txt` через `on_yearly_pulse_country`. On_actions складываются аддитивно (это же делают и E&F, и MR в пяти файлах), поэтому override исчез полностью.

### 3.3 Tesla

Оба триггера пересобраны с базы MR 2.8.3e; нормализованный diff показывает **только** наши добавления:

- `tesla_construction_sector_valid_for_improvement_trigger`: `+ building_ef_private_construction`
- `tesla_building_valid_for_mechanical_improvement_trigger`: `+ bg_bank`, `+ bg_financial_centre`, `+ bg_national_stockpile`, `+ bg_ef_private_construction` (у MR добавился `bg_subsistence_ranching`, он подхвачен из новой базы)

Патч по-прежнему нужен: у этих четырёх E&F-групп **нет** `parent_group`, поэтому MR-овские исключения `bg_government` / `bg_urban_facilities` их не ловят. `bg_silver_mining`, наоборот, наследуется от `bg_mining` и в исключения попадать не должен.

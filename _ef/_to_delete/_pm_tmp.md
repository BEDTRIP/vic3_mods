## Разбор вылета до меню (21.08.2026, первая сборка мода)

Первая сборка `ef currency merge` роняла игру **до главного меню** — то есть на
чтении базы, а не на входе в кампанию. Три бага в генераторе, все одного класса:
парсер конфигов, написанный «на регулярках по строкам», врёт на реальных файлах E&F.

### 1. Свип по файлу собрал вложенные блоки как самостоятельные ключи

`iter_blocks()` искал `^[ \t]*key = {`. Для поиска одного известного ключа это
нормально. Для прохода по всему файлу — нет: E&F пишет script value с отступом,
поэтому под тот же шаблон попадают вложенные `value = {`, `if = {`,
`subtract = {`, `multiply = {`.

В `zz_ef_cm_script_values.txt` оказалось **1130 «ключей», из них 658 мусорных**:

```
value = { 188   if = { 188   subtract = { 188   multiply = { 94
```

`value` на верхнем уровне `common/script_values/` — это ошибка разбора базы, и игра
умирает до меню. Признак в файле: два закрывающих отступа подряд, потом ключ без
отступа, которого не может быть.

**Вывод в правила:** обход «всех блоков файла» обязан считать глубину скобок.
Шаблон по началу строки годится только тогда, когда имя ключа известно заранее.

### 2. Смещения считались по одному тексту, срез брался из другого

Первая попытка чинить #1 отслеживала глубину по копии текста без комментариев, а
`block_span` резала исходную строку теми же индексами. `strip_comments` укорачивает
строки — значит после первого же комментария все смещения смотрят мимо.

Поймалось не глазами, а проверкой, которую я дописал заодно: «ключ, который мы
записали, должен совпадать с ключом, который мы прочитали». Она сразу упала на
`base_demande_currency`.

**Вывод в правила:** нельзя искать по очищенному тексту и резать по грязному.
Либо один и тот же буфер, либо сканер, который сам пропускает комментарии и кавычки.

### 3. Схлопывание списка добавляло строку к уже существующей

В статик-модификаторах E&F перечисляет все 95 валют с одинаковым значением
(`goods_output_<валюта>_c_mult = 0.01`) — это его способ сказать «та валюта, которую
страна на самом деле выпускает». Схлопывание 95 строк в одну работало, но `spe_uni_c`
**сам входит в эти 95**, и его строка обрабатывалась отдельной веткой «оставить как
есть». Итог: схлопнутая строка плюс оригинальная — модификатор в одном блоке дважды.

Не вылет, но тихая двойная арифметика. Выживший товар должен идти через ту же
дедупликацию, что и все остальные.

### Что теперь стоит между генератором и игрой

В `regen_ef_currency_merge.py` добавлена самопроверка, она гоняется автоматически
после каждой сборки и печатает `self-check: ok` или список проблем:

* имена под-блоков (`value`, `if`, `limit`, `entry`, `building_modifiers`, …) на
  верхнем уровне — список `NEVER_TOP_LEVEL` в скрипте;
* дублирующиеся ключи верхнего уровня внутри файла;
* баланс скобок с учётом комментариев;
* каждый записанный ключ начинается с того же имени, что был прочитан.

Плюс независимая сверка, которую я прогнал руками после починки:

| проверка | результат |
|---|---|
| 472 script value — все существуют в E&F | ✔ 0 лишних |
| 285 PM — все существуют в E&F | ✔ 0 лишних |
| типы модификаторов 432 → 56, ничего не выдумано | ✔ |
| `goods_input/output_spe_uni_c_add/_mult` живы | ✔ |
| дубли ключей внутри файлов | ✔ нет |
| строк `spe_uni_c` в каждом статик-модификаторе | ✔ ровно 1 |
| товаров в мегапаке | **106**, запас 22 |

`block_span` теперь тоже пропускает комментарии и кавычки — иначе одна фигурная
скобка в комментарии уводит границу блока, и все срезы после неё молча неверны.

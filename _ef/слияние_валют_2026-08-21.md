# Слияние валют в один товар — разбор и первый мод, 21.08.2026

## Коротко

`_ef/ef currency merge` собран и лежит в репозитории. **162 → 106 товаров**, запас
22 слота, Tech & Res остаётся целиком. Ни одна страна не теряет монетарную систему:
все 95 законов на месте, у каждой свой `pm_currency_*`, банк чеканит, здания платят
за ликвидность. Общим стал только товар на рынке.

Всё генерируется: `tools/regen_ef_currency_merge.py`.

## Что я перепроверил и где расходится с прошлым разбором

Проверял по файлам, а не по прошлым выводам — три пункта разошлись.

### 1. `ownership_type` значит не то

`common/buildings/buildings.md`, строка 96:

> `no_ownership` — can't own **other** buildings, dividends if any are payed to the state;
> `self` — can own only itself; `other` — building can own other buildings

То есть поле описывает, **чем здание владеет**, а не кто владеет им. Вывод «здание
без владения в компанию не берётся» из прошлого разбора не подтверждается
документацией.

Но и обратное не подтверждается практикой: я прошёл по всем 48 зданиям, которые
перечислены в `building_types`/`extension_building_types` ванильных компаний — **у
всех 48 `ownership_type = self`, исключений ноль**. Прецедента, чтобы компания
держала здание с `no_ownership`, в ванили нет. Плюс у E&F во всех 99 банковских
компаниях `building_bank` закомментирован — автор, похоже, пробовал.

Значит это не «нельзя», а «непроверено». Проверяется дешёвой пустышкой, как ты
проверял 128 и 100 престижных — см. фазу 3 ниже.

### 2. Курсы валют на переменных — подтвердилось, и это ключ ко всему

E&F определяет **36 семейств script value на каждую валюту, 3485 значений**. Я прошёл
по всем 36 и посмотрел, кто их вообще читает:

| | |
|---|---|
| живых (используются где-то ещё) | **22** |
| мёртвых (не упомянуты нигде за пределами файла определения) | **14** |

И вот что важно: **все четыре семейства, которые читают рыночные данные валюты, —
мёртвые**. `<CUR>_c_market_goods_buy_orders`, `_sell_orders`, `_delta`,
`_lake_ratio` не упомянуты ни в одном другом файле E&F. Туда же
`money_supply_verification_<CUR>`, `buy_<CUR>_order`, `sell_<CUR>_market_panel`.

Живые 22 — это `money_value_*`, `money_value_in_gold_*`, `stockpiling_*`,
`export_to/in_*`, `import_from/in_*`, `debt_in_national_currency_*`,
`currency_identifiers_*`. Все до одного работают на переменных страны и глобальных
переменных:

```
money_value_pound_sterling = { value = 0  add = global_var:money_value_pound_sterling_global_var }
money_value_target_real    = { add = var:money_value_target_1 }
```

Единственный живой потребитель рыночных данных валютного товара —
`<CUR>_price` → `base_demande_<CUR>_price` → `central_bank_overlord_currency_purchases`,
то есть ветка «сюзерен скупает валюту вассала». Она и так не работает: см. пункт 3.

**Поэтому слияние вообще возможно.** Оно не трогает ни курсы, ни денежную массу,
ни золотой и серебряный стандарт, ни резервы, ни долг, ни кризисы.

### 3. Управление валютой вассала уже выключено

Ты спрашивал, на что влияет управление валютой субъекта и нельзя ли через него не
дать вассалу засрать рынок. Ответ: сегодня — ни на что. В `building_bank`:

```
production_method_groups = {
    pmg_minting_type
    pmg_monetary_policy
    pmg_currency_type #caché
    #pmg_subject_currency_type #caché suppretion suite à trop de bug et peux d'apport sur le gamplay que du lord
}
```

Группа закомментирована самим автором. 95 `pm_subject_currency_*` существуют, но
недостижимы. Механики нет — влиять не на что.

### 4. Инфляция считается не по деньгам

Проверил все пять корзин `inflation_on_*`:

| корзина | товаров | из них валютных |
|---|---:|---|
| consumer_goods | 21 | нет |
| energy | 5 | нет |
| raw_material | 7 | нет |
| manufactured_goods | 9 | нет |
| military_equipment | 7 | нет |

**Цена денег в инфляцию не входит вообще.** Инфляция у E&F — средневзвешенное
отклонение цен реальных товаров.

Так что «сюзерен размазывает свою инфляцию на рынок» работает не через это число,
а через другой канал: цена самого валютного товара определяет, сколько здания
платят за ликвидность (`pm_market_liquidity_*`, вход 98) и сколько попы платят за
`popneed_currency`. Вот это после слияния становится общим в пределах рынка — и это
ровно тот эффект, который ты описывал.

### 5. E&F уже сегодня возит 38 мёртвых валют

95 законов и 95×3 PM против 57 живых товаров. То есть **38 `pm_currency_*`, 38
`pm_market_liquidity_*`, 38 записей `popneed_currency`, их типы модификаторов,
строки в статик-модификаторах и script value уже указывают на товары, которые автор
сам закомментировал**. Генератор перецеливает все 95, так что эти 38 чинятся заодно.

Побочный вывод, полезный на будущее: раз E&F с 38 висячими ссылками на товары
работает у тебя годами, ссылка на несуществующий товар — это строка в логе, а не
вылет.

## Что делает мод

Итог по товарам, пересчитано по файлам с учётом перекрытий по пути:

| слой | было | стало |
|---|---:|---:|
| ваниль 1.13.10 | 53 | 53 |
| + PSC | 57 | 57 |
| + E&F с хотфиксом | 122 | **66** |
| + Morgenröte | 127 | 71 |
| + Tech & Res | **162 — вылет** | **106** |

Запас до потолка — 22 слота. T&R добавляет 35, а не 39: `elgar_instruments`,

Девять товаров E&F после слияния: `gold` (INJECT в ванильный), `silver`, `bond`,
`manufacture_stock`, `agricultural_stock`, `mining_stock`, `railroad_stock`,
`mutual_funds`, `local_currency`, `spe_uni_c`.

Взят `spe_uni_c`: он уже `default` у `popneed_currency`, у него есть иконка и цвет,
и его закон никому не выдаётся историей — то есть ничего не надо переставлять.
Локализация переименована в «Валюта» / «Currency»: у каждой страны по-прежнему свой
**закон** о валюте, и в интерфейсе денежной системы виден именно он.

### Две ловушки, на которых генератор спотыкался

Обе стоят того, чтобы попасть в общие правила:

1. **`#end_tag_1` на одной строке с закрывающей скобкой.** E&F помечает конец
   валютных списков комментарием прямо после `}`. Любой шаблон вида
   «закрывающая скобка одна на строке» пробегает мимо неё и съедает следующую —
   на `popneed_currency` это ломало баланс скобок, в статик-модификаторах тихо
   оставляло одну строку из 95.
2. **Ключ товара внутри имени модификатора.** `\b` не срабатывает в
   `goods_input_pound_sterling_c_add`, потому что после `_c` идёт `_`. Замена «по
   границе слова» молча пропускает половину ссылок: `market.mg:X` меняется,
   `modifier:goods_input_X_add` — нет. В генераторе это два отдельных шаблона, и
   в комментарии написано почему.

## Что дальше

### Фаза 2 — `local_currency` как честно худший вариант (не сделано)

Сейчас страна без монетарной системы сидит на `pm_no_market_liquidity`, у которого
**вообще нет входа** — её здания за ликвидность не платят ничего. Это не «хуже», это
бесплатно. Твоя идея «−20% тем, кто на дефолтной валюте» закрывает дыру: дать
`pm_no_market_liquidity` вход `local_currency` и штраф к пропускной способности.

Это уже не слияние, а балансовое решение, которое затрагивает ~600 стран и 52 типа
зданий. Поэтому отдельным модом и после того, как слияние проверено в игре.

### Фаза 3 — престижные валюты (упирается в один тест)

Порядок такой, потому что пункты независимы и дешёвые идут первыми:

1. **Цена престижного варианта.** Ты пишешь, что престижные не дороже. Если так, то
   престижная валюта даёт имя, иконку, престиж за лидерборд и +до 20% throughput
   зданиям, которые её едят, — но не возвращает национальную цену денег. Это надо
   знать до того, как строить на этом дизайн: если цена общая, то «фунт дороже
   рупии» не получится ни при каком раскладе, и престиж остаётся украшением +
   бонусом к производительности.
2. **Владение зданием ЦБ.** Пустышка на 10 минут: взять `company_BasicBank`,
   дописать в `building_types` строку `building_bank`, зайти в игру, основать
   компанию и посмотреть, берёт ли она банк. Если да — дальше `possible_prestige_goods`.
   Если нет — менять `building_bank` на `ownership_type = self`, и вот это уже
   правка ядра E&F: банк получит доли владения, дивиденды, интерес ИИ к
   национализации, и всю денежную математику надо будет перепроверять.
3. Только если 1 и 2 зелёные — генерировать престижные валюты и компании ЦБ по
   шаблону. Имя из склонения тега («Русская валюта») — отдельная задача, у ванили
   для этого есть `dynamic_company_type_names`, посмотрю когда дойдём.

Если 2 красный — лимит всё равно закрыт, ничего не потеряно.

## Чеклист проверки в игре

Порядок: CMF → ETF → E&F → **ef hotfix** → **ef currency merge** → остальное.

1. **Старт кампании** — годно / не годно. Сборка с E&F+хотфикс+T&R раньше вылетала
   на входе (162 товара), теперь 106. Это главная проверка.
2. **Панель денежной системы** — закон валюты на месте, называется как раньше,
   у Британии «фунт стерлингов», у Дании «датская крона».
3. **Рынок** — в списке товаров одна «Валюта» вместо 57. Цена не должна быть
   прибита к 1: `fixed_price = no`, торгуется.
4. **Здание банка, любая страна** — чеканка идёт, `pmg_currency_type` выбрана
   автоматически по закону, выход товара 1.
5. **Любой завод** — вкладка Market Liquidity показывает вход «Валюта» 98.
6. **Страна без монетарной системы** (любой минор) — `local_currency` на рынке
   есть, попы её едят. Хотфиксовая выдача не сломалась.
7. **Курс к золоту** — открыть панель E&F у Британии и у Франции: курсы должны
   отличаться и меняться. Если оба замерли — значит я неправ насчёт переменных,
   и это надо чинить до всего остального.
8. **`error.log` после загрузки** — ожидаемо будут строки про валютные товары от
   исходных определений E&F, которые наши перекрытия заменяют. Если их сотни и
   это мешает — в генераторе можно переключиться на перекрытие файлов целиком,
   но это 12 МБ пина на `01_economic_currency_scripted_value.txt`, поэтому по
   умолчанию так не сделано.
9. **`error.log` после 5 игровых лет** — искать `spe_uni_c`, `local_currency`,
   `market_goods_is_currency`.

## Разбор вылета до меню (21.08.2026, первая сборка мода)

Первая сборка `ef currency merge` роняла игру **до главного меню** — то есть на
чтении базы, а не на входе в кампанию. Три бага в генераторе, все одного класса:
парсер конфигов, написанный «на регулярках по строкам», врёт на реальных файлах E&F.

### 1. Свип по файлу собрал вложенные блоки как самостоятельные ключи

`iter_blocks()` искал `^[ \t]*key = {`. Для поиска одного известного ключа это
нормально. Для прохода по всему файлу — нет: E&F пишет script value с отступом,
поэтому под тот же шаблон попадают вложенные `value = {`, `if = {`,
`subtract = {`, `multiply = {`.

В `zz_ef_cm_script_values.txt` оказалось **1130 «ключей», из них 658 мусорных**:

```
value = { 188   if = { 188   subtract = { 188   multiply = { 94
```

`value` на верхнем уровне `common/script_values/` — это ошибка разбора базы, и игра
умирает до меню. Признак в файле: два закрывающих отступа подряд, потом ключ без
отступа, которого не может быть.

**Вывод в правила:** обход «всех блоков файла» обязан считать глубину скобок.
Шаблон по началу строки годится только тогда, когда имя ключа известно заранее.

### 2. Смещения считались по одному тексту, срез брался из другого

Первая попытка чинить #1 отслеживала глубину по копии текста без комментариев, а
`block_span` резала исходную строку теми же индексами. `strip_comments` укорачивает
строки — значит после первого же комментария все смещения смотрят мимо.

Поймалось не глазами, а проверкой, которую я дописал заодно: «ключ, который мы
записали, должен совпадать с ключом, который мы прочитали». Она сразу упала на
`base_demande_currency`.

**Вывод в правила:** нельзя искать по очищенному тексту и резать по грязному.
Либо один и тот же буфер, либо сканер, который сам пропускает комментарии и кавычки.

### 3. Схлопывание списка добавляло строку к уже существующей

В статик-модификаторах E&F перечисляет все 95 валют с одинаковым значением
(`goods_output_<валюта>_c_mult = 0.01`) — это его способ сказать «та валюта, которую
страна на самом деле выпускает». Схлопывание 95 строк в одну работало, но `spe_uni_c`
**сам входит в эти 95**, и его строка обрабатывалась отдельной веткой «оставить как
есть». Итог: схлопнутая строка плюс оригинальная — модификатор в одном блоке дважды.

Не вылет, но тихая двойная арифметика. Выживший товар должен идти через ту же
дедупликацию, что и все остальные.

### Что теперь стоит между генератором и игрой

В `regen_ef_currency_merge.py` добавлена самопроверка, она гоняется автоматически
после каждой сборки и печатает `self-check: ok` или список проблем:

* имена под-блоков (`value`, `if`, `limit`, `entry`, `building_modifiers`, …) на
  верхнем уровне — список `NEVER_TOP_LEVEL` в скрипте;
* дублирующиеся ключи верхнего уровня внутри файла;
* баланс скобок с учётом комментариев;
* каждый записанный ключ начинается с того же имени, что был прочитан.

Плюс независимая сверка, которую я прогнал руками после починки:

| проверка | результат |
|---|---|
| 472 script value — все существуют в E&F | ✔ 0 лишних |
| 285 PM — все существуют в E&F | ✔ 0 лишних |
| типы модификаторов 432 → 56, ничего не выдумано | ✔ |
| `goods_input/output_spe_uni_c_add/_mult` живы | ✔ |
| дубли ключей внутри файлов | ✔ нет |
| строк `spe_uni_c` в каждом статик-модификаторе | ✔ ровно 1 |
| товаров в мегапаке | **106**, запас 22 |

`block_span` теперь тоже пропускает комментарии и кавычки — иначе одна фигурная
скобка в комментарии уводит границу блока, и все срезы после неё молча неверны.

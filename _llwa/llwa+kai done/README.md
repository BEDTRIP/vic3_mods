# ComPatch: LLWA + Kuromi's AI (+ Victorian Century)

**Game 1.13 (exe 1.13.11). Kuromi's AI 7.5; Locomotion: Land, Water, & Air (LLWA) 2.6.3; Victorian Century (declares no version).**

LLWA carries `common/ai_strategies/03_political_strategies.txt` at the **exact vanilla relative path** — and its content is a stale pre-1.13 copy: 125-line diff against current vanilla, the string "LLWA" does not appear anywhere in the file. Same relative path means a file-level override (rules file, section 3): the single latest mod's file at that path wins outright, and vanilla's own file at that path drops out of the merge entirely — not a key-by-key patch. LLWA loads last in the target chain, so its stale file wins, reverting all nine `ai_strategy_*` records it defines to their pre-1.13 shape, and — because a bare key with no prefix also overrides — wiping every `INJECT:` any earlier mod had already applied to those nine records. Nothing errors, nothing is logged.

## What was being lost

Machine matrix: 9 shared keys with KAI, all in `common/ai_strategies` (`tools/pair_matrix.py --pair "LLWA,KAI"`). Three different outcomes:

* **`ai_strategy_default` — not touched by this bug, not in this patch.** It isn't defined in `03_political_strategies.txt` at all (checked both LLWA's stale copy and current vanilla — absent from both). LLWA's only touch to it is a separate file, `LLWA_default_strategy.txt`, doing a plain `INJECT:subsidies` — additive, safe regardless of load order. Same reasoning as the already-closed LLWA × HC+GoB+MoH `noneed` on this key.
* **`ai_strategy_maintain_mandate_of_heaven` — touched by nobody but vanilla.** Not shared with KAI, VC, or TGR in the machine matrix. Restoring current vanilla at this path (file 1 below) is the whole fix; there's nothing to reapply on top.
* **The other seven** — `ai_strategy_conservative_agenda`, `_reactionary_agenda`, `_progressive_agenda`, `_egalitarian_agenda`, `_nationalist_agenda` (KAI-only, 5 keys, plain `INJECT:`s tuning AI weightings by ideology) and `ai_strategy_great_reforms`, `_tanzimat_reforms`, `_meiji_restoration` (three-way with **Victorian Century** too — the exact three keys LLWA also shares with VC, `LLWA.3`/plan) — all lose their earlier mods' contribution to LLWA's stale bare redefinition.

## What's in this patch

Three files, in this load order **within this mod** (filename sort: `0` < `z`):

1. **`common/ai_strategies/03_political_strategies.txt`** — byte-for-content copy of *current* vanilla, at the identical relative path. This mod loads after LLWA, so this file wins the same file-level override LLWA currently wins, and vanilla's real content is back in the merge for all nine keys (this alone fixes `ai_strategy_maintain_mandate_of_heaven`).
2. **`zzz_llwa_kai_political_strategies.txt`** — KAI's five pure-agenda `INJECT:`s, read live from KAI's own `kai_political_strategies.txt` and reissued verbatim on top of the restored vanilla base.
3. **`zzzz_llwa_kai_vc_reforms.txt`** — the three keys shared with VC too. Rather than re-derive the KAI × VC three-way merge a second time, this file copies the record bodies **verbatim, read live**, from the already-closed `_vc/kai+vc done/common/ai_strategies/zz_vc_kai_ai_strategies.txt` (addon-VC). This is also where the `ai_strategies` half of `_llwa/llwa+vc done` (LLWA × VC) is actually fixed — that folder's own README points back here instead of writing these same three keys a second time from a different generator, which would be exactly the "two compaches REPLACE_OR_CREATE the same record" mine the project's build-order rules warn about.

## How the merge is made

`tools/regen_llwa_kai.py`. File 1 is read straight from the vanilla install with asserts that vanilla still defines all nine keys at this path (and still does **not** define `ai_strategy_default` there, guarding the noneed reasoning). File 2 asserts KAI's five agenda records are still plain `INJECT:` before reissuing them. File 3 asserts the reused merge file still exists and still uses the expected prefixes (`INJECT:`/`REPLACE_OR_CREATE:`) for each of the three keys — any of these failing means a source changed shape and the generator stops instead of silently producing something wrong.

## Notes

* **Depends on `_vc/kai+vc done` existing** (addon-VC). Victorian Century is a permanent block in this set, not optional, so this isn't handled as an optional-dependency `.off` pair (rules section 8, decision #9) — if that ever changes, file 3 would need to move behind the same tag/`.off` convention used for VC in addon-HC.
* **Maintenance.** Everything is generated by `tools/regen_llwa_kai.py`. Re-run after LLWA, KAI, or the `kai+vc done` compatch updates; `--check` reports drift without writing.
* KAI declares workshop id `kai.kuromi`, version `7.5`; LLWA declares id `xyz.1230james.locomotion`, version `2.6.3`; Victorian Century declares neither, so it's named only in the description and `tested_with`.

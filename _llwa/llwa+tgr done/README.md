# ComPatch: LLWA + The Great Revision

**Game 1.13 (exe 1.13.11). The Great Revision 2.0 (id 3215078236); Locomotion: Land, Water, & Air (LLWA) 2.6.3.**

LLWA loads last in the target chain — after the megapack, Victorian Century, addon-VC, HC+GoB+MoH, and addon-HC — and its `REPLACE:` on ten rail production methods is a bare full body. Where TGR's own file adds a sub-block LLWA doesn't declare at all, that addition is silently gone from the loaded game. This patch restores it, on top of LLWA's own numbers.

## Load order

1. …CMF → ETF → TGR → PSC → KAI → E&F → E&F Hotfix → Morgenröte → PBE…
2. …megapack → VC → addon-VC → HC+GoB+MoH → addon-HC…
3. **LLWA**
4. **this ComPatch**

**This patch must load after LLWA.** LLWA is the mod doing the overwriting; the patch only re-adds what LLWA's overwrite ate.

## What was being lost

Machine matrix: 11 shared keys, 0 shared paths (`tools/pair_matrix.py`). 1 (`ai_strategy_default`) is **not a conflict** — see below. The other 10 are all in `common/production_methods`, all ten records in LLWA's own `LLWA_rails.txt`.

TGR's own numeric rebalance (higher `state_infrastructure_add`, different `goods_output_transportation_add`, etc.) is **not** restored here — LLWA loads last in the target chain, so LLWA's own numbers are the legitimate winner in the finished game regardless of this patch, and reinstating TGR's numbers would silently overrule LLWA's design instead of fixing a loss.

What genuinely is lost: TGR adds a `state_modifiers.unscaled = { state_market_access_price_impact = 0.05 }` sub-block that LLWA's body does not declare in any form (not a differing value — an absent key), on:

* `pm_early_trains`, `pm_steam_trains` (+ `_principle_transport_3`), `pm_electric_trains` (+ `_principle_transport_3`), `pm_diesel_trains` — under `state_modifiers`.
* `pm_diesel_trains_principle_transport_3` — under `building_modifiers` in TGR's own file (every other entry uses `state_modifiers`; almost certainly a copy-paste slip on TGR's side, reproduced here exactly as TGR wrote it rather than "corrected", per the project rule against fixing a symptom before understanding it).

The remaining three rail methods LLWA shares with TGR — `pm_no_passenger_trains`, `pm_steel_passenger_carriages`, `pm_wooden_passenger_carriages` — are **also** shared with Victorian Century. That restoration (VC's `building_modifiers.unscaled.building_job_attractiveness_mult`) lives in `_llwa/llwa+vc done`, not here, so one record isn't written twice across two compaches (VC's REPLACE_OR_CREATE would collide with a second copy of the same key).

### `ai_strategy_default` — noneed, not in this patch

LLWA touches `ai_strategy_default` only via a dedicated file, `LLWA_default_strategy.txt`:

```
INJECT:ai_strategy_default = {
    subsidies = { ... }
}
```

Purely additive — an `INJECT:` into a `subsidies` sub-block TGR doesn't touch at all. It survives regardless of load order, the same reasoning already recorded for the LLWA × HC+GoB+MoH `noneed` (`ai_strategy_default`: MoH `REPLACE:`, LLWA `INJECT:subsidies`). This does **not** come from LLWA's stale `03_political_strategies.txt` — that file doesn't define `ai_strategy_default` at all (checked: `grep -n "^ai_strategy" 03_political_strategies.txt` in both LLWA's copy and current vanilla, `ai_strategy_default` is absent from both — it lives elsewhere in vanilla's `common/ai_strategies/`).

## What's in this patch

One file, `common/production_methods/zz_llwa_tgr_rails.txt`, seven full `REPLACE_OR_CREATE:` records — LLWA's own body for each, with TGR's `unscaled` sub-block added back (under whichever parent TGR itself used).

## How the merge is made

`tools/regen_llwa_tgr.py`. Reads LLWA's and TGR's current `LLWA_rails.txt` / `TGR_TRADE_private_infrastructure_railway.txt` live (never hand-copied), locates whichever top-level sub-block TGR nests `unscaled` under for each record (doesn't assume — six are under `state_modifiers`, one under `building_modifiers`), asserts the extracted content is still exactly `state_market_access_price_impact = 0.05` (fails loudly if TGR's file changes shape), and splices it into LLWA's own body at the matching depth. Per the project's still-open rule on `REPLACE:` sub-block semantics, every record here is written as a full body.

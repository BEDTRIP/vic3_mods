# MEGAPACK ONLY -- this file does not exist in any of the eight ComPatches.
#
# Two of them REPLACE: these same two buildings, for two different reasons, and
# inside one mod files load by name:
#
#   zz_tr_kai_tgr_buildings.txt   (TGR + T&R)  T&R's body + TGR's building_group
#   zztr_vanilla_buildings.txt    (E&F + T&R)  T&R's body + E&F's two PM groups
#
# zztr_ sorts after zz_tr_, so the E&F + T&R copy is the one the game keeps and
# TGR's building_group is dropped. That matters: TGR creates its own
# bg_industry_heavy / bg_industry_light (children of bg_manufacturing) and keys
# its industry decree (TGR_POLITICS_decree.txt), its economic-incentive laws
# (TGR_POLITICS_economic_incentives_industry.txt) and its building_group_*
# modifier types off them. T&R's bg_heavy_industry is a SIBLING group, not a
# parent, so is_building_group never reaches it -- these two buildings silently
# fall out of TGR's decree and incentive laws. Nothing is written to error.log:
# the trigger is not broken, it simply answers no.
#
# The bodies below are zztr_vanilla_buildings.txt's (generated by
# tools/regen_ef_tr_copies.py from T&R's current file, with E&F's two groups
# appended) with only building_group swapped to TGR's, which is exactly the one
# line zz_tr_kai_tgr_buildings.txt carries over.
#
# Price of the choice, same as in the TGR + T&R patch: T&R's
# building_group_bg_heavy_industry_throughput_add bonuses (environmental policy
# laws, two automotive companies; +-0.01..0.02) no longer reach these two
# buildings. Judged the smaller loss there and here.
#
# REPLACE: and not INJECT: because building_group is a scalar -- there is no list
# to append to, and INJECT: on a scalar is not a behaviour this repo has ever
# verified in game. A full REPLACE: is correct under either reading of how 1.13
# applies database prefixes.
#
# !! MAINTENANCE !! Re-derive from zztr_vanilla_buildings.txt after every T&R
# update -- that file is generated, this one is not.

# Прогон игры в песочнице (`tools/run_vic3_sandbox.ps1`)

Агент сам запускает Victoria 3 на ПК пользователя, ИИ играет за все страны (и за игрока), скрипт
крутит время на скорости 5, закрывает игру и собирает логи. Сделано 1.10.2026 (EF.48).

## Перед запуском — обязательно

1. **Игра закрыта** (`tasklist | grep -i victoria` пусто), иначе скрипт падает с «already running».
2. **Живая копия мода синхронизирована** (`Documents/…/Victoria 3/mod/E&F Hotfix` = репозиторий,
   `diff -rq` без расхождений, кроме `_to_delete`). **Пока игра идёт — НЕ синхронизировать**: в
   `-debug_mode` игра на лету перечитывает изменённые файлы, и error.log наполняется ложными ошибками
   (эффекты перечитаны, а новые script values — нет).
3. **Экран и клавиатура заняты** на всё время прогона. Если пользователь за ПК — предупредить. Скрипт
   перед каждой клавишей и щелчком проверяет, что игра на переднем плане; если Windows не отдала фокус
   (пользователь работает в другом окне), прогон останавливается, ничего не нажав (1.10: без этой
   проверки «enable_ai all» напечаталось в чат пользователя).
4. Продолжение сейва: **последний сейв должен быть за страну, не в режиме наблюдателя** — в
   наблюдателе игра не выполняет GUI-команды, мост GUI → скрипт (EF.48) молчит.
5. **Ручные сейвы пользователя не трогать**: только читать. `-StartSave` работает через копию.

## Из облачной сессии (claude.ai/code, Linux) — через мост `vic3-pc` (5.10)

Облачная сессия не видит ПК: игра, `Documents/…` и PowerShell есть только у MCP-сервера `vic3-pc`
(`tools/pc_bridge/server.py`, туннель ngrok, `.mcp.json`; на ПК запускается `tools/pc_bridge/start.ps1`).
Нет инструментов `mcp__vic3-pc__*` — мост выключен, попросить пользователя запустить `start.ps1`.

1. Правки — в своём клоне, **коммит и `git push` в `main`** (мост берёт код с GitHub, не из облака).
2. `checkout(branch)` → `_bridge/wt` на ПК; `sync_mod()` (по умолчанию `_ef/ef hotfix 1.13` → `E&F Hotfix`;
   другие моды — `repo_folder`, `live_name`); при идущей игре отказывает.
3. `start_run(run_minutes, new_game, tag, start_save, autosaves, shots, countries, …)` — те же параметры, что
   у скрипта ниже; сразу отдаёт id. Дальше `run_status(id)` раз в 1–2 минуты (в облаке ждать фоновой
   командой Bash `sleep 120` с `run_in_background` — обычный `sleep` заблокирован), пока не «finished». Игра встала («Конец игры») — `stop_run(id)`, логи тогда в `docs/logs`.
4. Чтение: `list_dir` / `read_text` (`from_end`) / `grep` по путям `runs/<id>/…`, `docs/logs/…`,
   `docs/crashes/…`, `game/game/…`; снимки — `get_image(path, crop=[x0,y0,x1,y1])` (доли, кадрировать
   подсказку, а не весь экран); `py_tool("parse_eflog" | "save_money_check", args)` — разбор на ПК.
5. Скрипты репозитория на ПК — `py_tool(name, args)`, `name` без `.py`; запускаются из `wt`. Поимённо — разбор сейвов
   (`parse_eflog`, `save_money_check`, `save_ownership`, `save_ownership_transfers`, `save_construction_goods`,
   `save_measure_ef`), по маске `PY_TOOL_GLOBS` — генераторы и анализаторы (`regen_*`, `build_addon*`, `pair_matrix`,
   `content_holes`, `check_*`, `scan_*`, `stale_bodies`, `replace_audit`, `loc_dead_overrides`, `list_lawgroups_diff`).
   Пути вида `docs/…`, `runs/…`, `orig/…` в `args` переводятся в пути ПК; остальные (`tools/blocks.json`) — от корня `wt`.
   `vic3_mods_out` (30 ГБ, в облако не перенести) и `_tmp_analysis` видны скриптам через ссылки-junction
   `_bridge/vic3_mods_out`, `_bridge/_tmp_analysis` (их делает `start.ps1`), так что `../../vic3_mods_out` из
   `wt/tools` работает. Пример: `py_tool("pair_matrix", ["--blocks", "tools/blocks.json", "--pair", "E&F+hotfix,PSC"])`.
6. **Генератор на ПК → коммит в облаке:** правка генератора здесь, коммит и `git push` → `checkout(branch)` →
   `py_tool("regen_…", [])` (пишет в `wt`) → `wt_diff()` отдаёт изменения `wt` патчем (`git add -A -N` + `git diff --binary`,
   новые файлы тоже) → сохранить в scratchpad, `git apply --check`, `git apply`, проверить `git diff --stat`, коммит и
   push как обычно. Результат генератора живёт в `wt` только до следующего `checkout` (`git clean -fdq`) — забирать
   `wt_diff` сразу. Если патч велик для ответа — генератор по частям или `read_text` по файлам из его вывода.
   Проверено 5.10: `regen_ef_cb_loan` на `main` → `wt_diff` пустой (вывод совпал байт в байт, шума CRLF нет); новый файл
   (`check_megapack_conflicts --out tools/_wt_diff_test.md`) пришёл как `new file`, `git apply` в облаке дал тот же хеш
   блоба. Патч идёт через ответ инструмента — для `git apply` его нужно записать файлом (Write), так что большие
   патчи (десятки файлов локализации) удобнее забирать `read_text` по путям из вывода генератора или делить запуск.
   Генераторы пишут относительно репозитория (`regen_ef_cb_rate_loc` до 5.10 писал в основную копию ПК — исправлено).
   При лишних «изменениях» во всех строках смотреть `git diff --ignore-cr-at-eol` и не коммитить шум.

## Три режима

Запуск всегда в фоне (`run_in_background: true`), вывод — в `-OutDir` (scratchpad сессии):

```bash
# 1) новая игра с 1 января 1836 — нужна, когда менялись условия старта (история, законы, здания):
powershell -ExecutionPolicy Bypass -File tools/run_vic3_sandbox.ps1 -NewGame -Tag BUG -RunMinutes 10 -OutDir "<scratch>\runN"

# 2) продолжение последнего сейва (continue_game.json; кампания идёт дальше от прогона к прогону):
powershell -ExecutionPolicy Bypass -File tools/run_vic3_sandbox.ps1 -RunMinutes 10 -OutDir "<scratch>\runN"

# 3) старт с выбранного сейва (копия в sandbox_start.v3, оригинал не меняется):
powershell -ExecutionPolicy Bypass -File tools/run_vic3_sandbox.ps1 -StartSave "великобритания_1836_04_13.v3" -RunMinutes 10 -OutDir "<scratch>\runN"
```

Окончание ждать фоновым `until grep -q "\] done: C:\|stopping\|not in front" <OutDir>/stdout.txt; do sleep 10; done`
(с `-Shots` строки «vic3_ui done:» идут раньше конца — ловить именно «] done: C:», 4.10).

Параметры: `-RunMinutes N` (реальные минуты на скорости 5), `-Autosaves N` (остановиться после N новых
автосейвов; автосейв раз в полгода), `-Tag` (страна новой игры, по умолчанию BUG — Буганда: 2.10 пользователь заметил, что страна игрока под
`enable_ai all` ведёт себя пассивно — Британия ничего не делала с казной; играть за страну, которая на мир не влияет), `-AiTag` (консоль
`enable_ai <tag>`, по умолчанию `all`; `""` — не включать), `-LoadWaitSec` (предел ожидания загрузки, по
умолчанию 400). `-NoDumps` оставлен для старых команд и ничего не делает: `debugcountrybudgets` /
`debugmarkets` есть строками в `victoria3.exe`, но консоль релизной сборки отвечает «Unknown command».

## Снимки подсказок и бюджета (4.10)

`-Shots` — в конце прогона (на паузе) снять у своей страны подсказку валюты (там «Денежная масса», M0–M3 и
все счета), семь карточек счетов (наведение на ссылки внутри закреплённой подсказки) и все вкладки бюджета
постранично; `-Countries "GBR,USA,RUS"` — потом пересесть (`tag`) за каждую и снять то же. Файлы
`<TAG>_currency.png`, `<TAG>_card_<счёт>.png`, `<TAG>_t<N>_<вкладка>_<стр>.png` в `-OutDir`. Ничего не
играется за них: игра на паузе. ~3 мин на страну.

Руками по открытой игре — `tools/vic3_ui.ps1 -OutDir <dir> -Do "shot x; hover 0.1 0.09; macro cards GBR; close"`
(игру оставляет `-KeepOpen`; `close` закрывает её и собирает логи). Точки и последовательности — в
`tools/vic3_ui_points.ps1` (доли окна 2560×1440, русский интерфейс), общие функции — `tools/vic3_ui_lib.ps1`.
Что выяснено: бюджет открывается **F2** (не переключает — закрывать крестиком панели); колонка значков слева
при наведении разворачивает подписи поверх вкладок панели — перед щелчком увести мышь; подсказка
закрепляется через ~2 с, после чего мышь можно завести внутрь (вложенные подсказки карточек); колесо над
картой меняет масштаб карты, а не панели. Строки карточек сдвигаются на строку, если у страны иначе
переносится шапка подсказки — снимки проверять глазами.

Зачем снимки (пользователь, 5.10): пересаживаться между странами и смотреть, что у них происходит, —
`-Countries` и `country <TAG>` в `vic3_ui.ps1`. Подсказка валюты и карточки — только у стран с ЦБ (курс
«₣ = 0.74» в верхней панели); у страны без него снимки пустые. Пользователь за ПК может сам пересесть за другую страну посреди
снимков (5.10: карточки и бюджет «BUG_*» сняты за Францию) — сверять флаг на снимках.

`error.log` ротируется и в короткий прогон (3 мин — 21 тыс. строк): части журнала скрипт сохраняет в
`errparts/` и во время загрузки, так что ошибки загрузки остаются.

## Что делает скрипт

- Новая игра: главное меню → «Новая игра» → «Песочница: начать игру» → «Случайное государство» →
  «Начать» → консоль `tag <Tag>` (смена страны — **`tag`**, не `play`). Щелчки — в долях окна, сняты на
  2560×1440 (16:9).
- Экраны распознаются по среднему цвету участка (`Wait-Screen`: кнопка «Новая игра», угол экрана целей,
  море в лобби, левая колонка значков в игре), а не фиксированными паузами. Новая игра: от запуска до
  хода ~2 мин; продолжение: загрузка ~1 мин. Если экран не распознан за предел — скрипт идёт дальше.
- Консоль: клавиша левее «1»; закрывается щелчком по карте + той же клавишей (Escape при фокусе в
  строке ввода её не закрывает — клавиша скорости «5» уходила в консоль).
- Проверка хода — по дате на экране (debug.log буферизуется до выхода). Стоит — снимает паузу.
- В конце: пауза, скриншот, закрытие, копия всех логов, `eflog.txt`.

**Скорость:** скорость 5 ≈ 1 игровой год за 3.5 реальной минуты в начале; 3.10 с зондами и полным миром — 
≈ 5 минут на год (36 мин: 1836 → 1843.2; 48 мин → 1845.7; 27 мин → 1841.7).

## Что читать после прогона

- `run.log` — ход прогона; «the game exited» до конца = **вылет**: смотреть
  `Documents/…/Victoria 3/crashes/victoria3_<дата>_<время>/` (`exception.txt`, `logs/debug.log`,
  `logs/error.log` — последние строки перед вылетом).
- `eflog.txt` — недельные строки денежной модели: `EFW|дата|страна|ключ значение|…` (шаг) и `EFR|…`
  (приёмник моста). Разбор в JSON: `py tools/parse_eflog.py <run>/eflog.txt <out.json>` →
  `{страна: {"EFW": [{date, ключ: значение}], "EFR": [...]}}`.
- `error.log` — `grep "zz_ef"` (наши файлы) и ошибки сразу перед вылетом.
- Скриншоты `00*` (меню/лобби новой игры), `01_loaded`, `01b_ai`, `03_end`.
- **Сверка счетов с сейвом** (UI.9, 3.10): `py tools/save_money_check.py [сейв] [TAG …]` — казна, касса предприятий
  (Σ cash_reserves), пул, точный недельный бюджет движка (`weekly_income/expenses`), переменные модели и её последний
  шаг (`zz_ef_prev_*`); сравнивать с подсказкой денег той же даты.
- Сейвы — текстовые, ~450 МБ; парсить Python-скриптом по ключам (переменные: `flag=<имя>` +
  `identity=<значение×1e5>`, отрицательные — uint64).

## Известное

- 1.10.2026: кампания, дошедшая до 1844, вылетает (EXCEPTION_STACK_OVERFLOW) через 1–4 с после
  недельного расчёта — и со старой версией модели, и с выключенной. Причина не найдена (План проекта,
  блок В). Для проверок до 1844 — новая игра.
  3.10: две новые игры (e0_2 до 1845.7, e0_3 до 1841.7) — без вылета; вылет был у старой кампании.
- Находки прогонов — сразу в `План проекта.md` (правило проекта), а не только в ответ.
- 2.10.2026: **Буганду (страна по умолчанию) могут аннексировать** — прогон 1836 → 1839.10 встал на
  экране «Конец игры» («Вас аннексировали!»), скрипт видит это как «date stands». Игру закрыть
  вручную (`Stop-Process`), логи скопировать из `Documents/…/logs`. Для длинных прогонов — страна,
  которую не съедят (`-Tag`).
- 2.10.2026: **не читать `run.log` в цикле, пока скрипт пишет** — `Add-Content` упал с «поток
  недоступен для чтения», скрипт прервался, игра осталась открытой. Ждать окончания по выходу
  фоновой задачи, а не опросом файла.
- `error.log` в `-debug_mode` ротируется по ~0.5 МБ (`error.1..5.log`): за 20 минут стартовая часть
  (ошибки загрузки) пропадает. Нужна загрузка — короткий отдельный прогон.
- Снимки по годам: автосейвы ротируются (`autosave`, `_1…_4`) — копировать каждый новый
  `autosave.v3` фоновым циклом в scratchpad (≈450 МБ штука). Разбор владения уровнями и пула —
  `building_ownership_manager` (владелец — `identity={ building=… }` или `{ country=… }`),
  `investment_pool=` и `previous_building_group_investments` в записи страны.
- 4.10 ночью: окно игры при запуске не вышло вперёд (впереди был Obsidian) — «меню» распознано по
  цвету чужого окна, дальше экраны не найдены, проверка фокуса остановила скрипт, ничего не нажав; игра
  вылетела в меню (ACCESS_VIOLATION, `crashes/victoria3_01260904_041618`). Повтор через минуту прошёл.
  4.10 вечером повторилось (игра стартовала за окном пользователя). Исправлено: `Wait-Screen` перед каждым
  замером цвета выводит игру вперёд (`Raise-Game`) и верит участку экрана только при игре впереди.

## Где что лежит

```
vic3_mods/                 наша работа
  _<блок>/                 парные компачи блока: <A>+<B> done | noneed | out
  __megapacks/             сведённые мегапаки основной пачки
  __addon/                 собранные аддоны (VC, HC+GoB+MoH, LLWA)
  архив/                  закрытые группы задач
  tools/                   инструменты и генераторы
  tools/_to_delete/        то, что отслужило: разборы закрытых пар, старый кэш
vic3_mods_out/             распакованные чужие моды, руками не править
_tmp_analysis/             кэш индексов и черновики прогонов
```

Суффикс папки компача — это его статус: `done` (написан), `noneed` (проверено,
не нужен), `out` (чужой компач как источник), `out fixed` (чужой, поправленный).

## Чеклист начала сессии

1. Прочитать этот файл и раздел плана по нужному блоку — больше ничего заранее не читать.
2. Задача про совместимость двух модов → `pair_matrix.py --pair "A,B"`.
3. Задача про аддон или про «а не потерялось ли что-то» → `content_holes.py`,
   разделы `registry` и `builds` в первую очередь.
4. Правила по движку открывать, когда упёрся в конкретный префикс или порядок, а не заранее.
5. Что-то выяснилось и переживёт сессию — записать сразу: правило в правила,
   решение в план, историю в архив. Не копить до конца работы.

## Два инструмента, и оба нужны

`pair_matrix.py` меряет пересечение ключей, которые определяют **оба** мода.
`content_holes.py` меряет три класса, которых первый не видит по устройству:
новый контент, которого нет в чужих рукописных списках; чужие компачи вне блока;
уже собранные мегапак и аддоны, поверх которых грузится следующий блок.

Статус `noneed`, поставленный по одному из них, дважды оказывался неверным
(LLWA × E&F, HC+GoB+MoH × E&F). Ставить только после обоих.

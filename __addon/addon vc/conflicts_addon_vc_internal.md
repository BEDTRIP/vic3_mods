## 1. Required work — done

**The one real assembly conflict: `common/buy_packages/wealth_1`…`wealth_99`.** Three of the four pair compatches restore different fields of the same 99 records: `tgr+vc` (full `REPLACE_OR_CREATE:`, all 99), `ef+vc` (`INJECT:`, all 99), `morg+vc` (`TRY_INJECT:`, wealth_10 up, 90). Copied in as three files they sort `zz_vc_ef_buy_packages.txt` < `zz_vc_morg_buy_packages.txt` < `zz_vc_tgr_buy_packages.txt`, so TGR's full-body file would load last inside this one mod and silently wipe E&F's and Morgenroete's fields all over again — the exact bug each of those two compatches was written to fix against VC, reintroduced one layer up. Fixed by `tools/regen_addon_vc.py`: one merged file, TGR's body plus E&F's and Morgenroete's fields appended into the same `goods` sub-block, generated fresh on every build. No field-name collisions exist between the three sources on any of the 99 records (checked programmatically for all 99, not sampled).

No other cross-compatch key or path collision exists in the four "done" pairs (`tgr+vc`, `ef+vc`, `morg+vc`, `kai+vc`) — verified by walking every `common/*.txt` file in all four compatch folders and grouping by (category, key); exactly 100 (category, key) pairs are touched by more than one pair, 99 of them the `buy_packages` case above and 1 the `base_values` non-conflict below.

# Addon: Victorian Century x MegaComPatch

Built 26.08.2026 for game 1.13 (exe 1.13.11).

This is the layer that puts **Victorian Century** on top of the MegaComPatch set (The Great Revision, Private Sector Construction, Kuromi's AI, E&F, Morgenroete, Power Blocs Expanded). The megapack covers its own six blocks; VC is the next block added above it, and this addon closes VC against everything below.

It is a merge of four pair compatches kept separately in the repository, plus one file the assembly itself needs (see below):

| compatch | pair | status |
| --- | --- | --- |
| `_vc/tgr+vc done` | VC x The Great Revision | 20 files |
| `_vc/ef+vc done` | VC x E&F (+ Hotfix) | 4 files |
| `_vc/morg+vc done` | VC x Morgenroete | 3 files |
| `_vc/kai+vc done` | VC x Kuromi's AI | 1 file |
| `_vc/psc+vc noneed` | VC x Private Sector Construction | **no file — confirmed `noneed` (VC.5)** |
| `_vc/pbe+vc noneed` | VC x Power Blocs Expanded | **no file — confirmed `noneed` (VC.6)** |

Every file is generated by the four `tools/regen_vc_*.py` scripts out of the mods themselves, plus one more file generated by `tools/regen_addon_vc.py` that only the assembly needs (see "The one file this addon adds" below). Assembled by `tools/build_addon_vc.py`. Nothing here is hand-edited.

**This addon must load after Victorian Century.** That is the whole point: VC is the mod doing the overwriting, on top of every block below it.

**Victorian Century, if you use it, before Hail, Columbia!** — VC ships 55 files at vanilla paths with bare bodies, including the Chinese and Ottoman history files and all eight interest groups; loaded after Hail, Columbia! + Gates of the Bosphorus + Mandate of Heaven it would eat those mods' own merges. This addon does not touch that pair at all (VC x HC+GoB+MoH is HC.7 in the project plan, a separate layer still to be written) — it only closes VC against the six blocks of the main pack.

## What this addon does

### The Great Revision comes back on top of VC, almost everywhere

VC re-declares a large share of what TGR had already rewritten — the eight interest groups, 99 buy packages, twelve companies, German unification, eight pop needs, `base_values`, eight country histories, four parties, two government types, formable GER, the Canada/Australia decisions — 172 shared keys and 14 shared paths in total. This addon's TGR file (`zz_vc_tgr_*.txt`, 20 files) puts all of it back on top of VC's own numbers, as a genuine three-way merge against vanilla rather than a pick-one-side patch: VC's rebalance of services/leisure/luxury items survives right alongside TGR's rebalance of food and drink, VC's 31-state Frankfurt-gated Germany survives alongside TGR's buttons and Bismarck event, VC's three-interest-group party coalitions survive alongside TGR's other party tuning.

The one part that is not a merge: **1725 ideology stances**, hand-placed because neither mod's files contain anything to derive them from — VC's 56 ideologies had no opinion on any of TGR's 60 laws, and none of TGR's 48 ideologies had one on VC's 10. Placed from a workbook (`_vc/tgr+vc done/vc_tgr_ideology_grid.xlsx`) that ships beside the compatch; edit it and re-run `tools/regen_vc_tgr.py` to change them.

### E&F's currency demand, opium plantation, Standard Oil and minting bonus come back

VC's full-body overwrites silently dropped four things E&F had injected: `popneed_currency`/`popneed_financial_products` on all 99 buy packages, two production-method groups on the opium plantation (the one building VC bare-`REPLACE:`s instead of injecting), two prestige goods on Standard Oil, and an icon plus `country_minting_add = -500` on `base_values`. All four come back. The `base_values` fix is the one judgement call in this addon: VC's own `country_minting_add = 1000` and E&F's `-500` are both `_add` fields, which Victoria 3 sums rather than letting the later one win — so the restored file nets +500, the same result both mods running together would produce if VC's overwrite weren't in the way.

### Morgenroete's entertainment demand, three pop needs and two characters come back

90 buy packages lose Morgenroete's `popneed_entertainment`, three pop needs lose one to three of Morgenroete's own goods entries, and Charles Dickens / Karl Johan Bernadotte lose a role, several traits and an `on_created` effect. All restored. One item stays deliberately open — see below.

### Kuromi's AI's political-strategy tuning comes back where it's safe to

VC's overwrites on three AI strategies dropped KAI's `revolution_aversion` tuning. `ai_strategy_great_reforms` and `ai_strategy_tanzimat_reforms` get it back by plain `INJECT:`. `ai_strategy_meiji_restoration` is a genuine three-way rewrite — VC replaces the whole record for its own Meiji content, KAI tunes two numbers and also changes an interest-group weighting that depends on a vanilla journal entry VC's own parallel Meiji system may or may not still fire. Only the two numbers are restored here; the interest-group change stays open — see below.

### Private Sector Construction and Power Blocs Expanded need nothing

Both pairs were re-confirmed `noneed` on 26.08.2026 (VC.5, VC.6). PSC and VC both only add `_add`-suffixed fields to the same four construction methods, and Victoria 3 sums repeated `_add` fields rather than letting the later one win, so nothing is lost either way. PBE's one shared script value never overrides anything in the first place — it's a bare key repeat where the game requires `REPLACE_OR_CREATE:`, so PBE's contribution is dead with or without VC. This addon works unchanged whether or not you run either of those two mods.

## The one file this addon adds — and why

Three of the four pair compatches above restore something into the *same* 99 `common/buy_packages/wealth_N` records: TGR's file is a full `REPLACE_OR_CREATE:` (it has to be — TGR's numbers are multipliers on VC's, not additions), while E&F's and Morgenroete's are plain `INJECT:`/`TRY_INJECT:` of a couple of extra fields each.

Copied into one mod as three separate files, they sort `zz_vc_ef_buy_packages.txt` < `zz_vc_morg_buy_packages.txt` < `zz_vc_tgr_buy_packages.txt` — so TGR's file, which never mentions E&F's or Morgenroete's fields, would load **last** and silently wipe both of their restorations all over again. That is precisely the failure mode all three compatches individually exist to fix against Victorian Century; assembling them naively would just reproduce it one level up, with this addon eating its own ingredients.

Section 8 of the working rules calls this "two compatches `REPLACE:` the same record, each for its own line" and prescribes one file, loaded last, carrying the merged body. `tools/regen_addon_vc.py` generates exactly that: `common/buy_packages/zzzz_addon_vc_buy_packages.txt`, TGR's body with E&F's and Morgenroete's fields appended into the same `goods` sub-block. All three restorations survive together, regardless of file name order. It is generated fresh every time `tools/build_addon_vc.py` runs — there is no separate command to remember, and no way for it to go stale relative to the three pair compatches it reads from.

No field-name collisions exist between the three sources for any of the 99 records (verified programmatically, not sampled), so the merge is a plain concatenation into each record's `goods` block, not a judgement call.

## Open questions carried over from the pair compatches

Neither is new to this addon — both were left open in their own pair's analysis, and assembling the addon doesn't change either.

* **`mobilization_option_chemical_weapons`** (Morgenroete x VC). Morgenroete sets `upkeep_modifier.goods_input_fertilizer_add = 2`, VC sets the same field to `0.5` inside its own `upkeep_modifier` sub-block on the same record. Whether repeated `_add` keys *inside one record's own sub-block* sum (as confirmed for the country-wide `base_values` pool above) or the later declaration wins outright is not established for this shape. No file written — guessing wrong either loses Morgenroete's fertilizer cost or triples it. Cheap in-game check: look at the actual fertilizer upkeep of the chemical-weapons mobilization option with Morgenroete + VC active.
* **`ai_strategy_meiji_restoration` — `anti_interest_groups` / `interest_group_government_weight`** (Kuromi's AI x VC). KAI drops `ig_armed_forces` from the static anti-list and replaces it with a conditional penalty gated on vanilla's `je_meiji_army` journal entry. VC reworks Meiji Restoration with its own journal entries and doesn't add `je_meiji_army` itself. Whether that journal entry — or KAI's other trigger, `je_meiji_main` — ever becomes true under VC's own Meiji track isn't established from the files. See `_vc/kai+vc done/conflicts_vc_vs_kai_report.md` for the cheap in-game check.

Two more items are tracked separately in the project plan, not here: **VC.7** (which of the ten prestige goods VC/HC/MoH/E&F overfill should give up their slot — an editorial call, not a technical one) and **VC.10** (a letter to VC's author about a malformed law value and the map/journal files this addon doesn't touch).

## Checked and deliberately not touched

* **41 of 42 shared `common/buildings` keys**, the shared `common/defines` groups, and the shared `mutual_funds` technology (E&F x VC) — both sides only inject into disjoint sub-blocks or disjoint fields in every one of these; verified across every shared key, not sampled.
* **`common/technology/technologies` (TGR x VC, 6 keys) and `common/production_methods` (TGR x VC, 3 keys)** — same shape, disjoint sub-blocks.
* **`manifest_destiny.txt`** — VC blanks it with an 11-byte stub, TGR's rework goes with it. Not restored on purpose: if you also run the HC+GoB+MoH addon, Hail Columbia kills the same file again with its own 1100-line journal chain, so restoring TGR's version here would only be visible in sets without HC — and that layer isn't built yet (HC.7).
* **`common/dna_data/ecchi_ger_hitler.txt` (Morgenroete x VC)** — same portrait data from both mods, reformatted; VC wins the path and nothing of Morgenroete's own is lost.
* **`common/ship_types` and the `NAI` defines (Kuromi's AI x VC)** — disjoint sub-blocks / disjoint constant names.
* **Localization, event ids** — zero collisions across all four pairs, checked per pair and re-checked at assembly (`scan_conflicts.py`, see below).
* **Goods** — this addon adds none. The set stays at 74 of the 128 ceiling; Victorian Century has no `common/goods` folder at all.

## Checks run against the assembly

* **Coverage.** Every file in every one of the four compatches is either copied byte-for-byte or is one of the three `buy_packages` sources folded into the merge above (declared, not silent — see `conflicts_addon_vc_internal.md`).
* **Internal.** Brace balance, encodings, duplicate top-level keys (two declared: the additive `COUNTRIES` container, same exception as the HC+GoB+MoH addon; `base_values`, TGR's and E&F's `INJECT:` on disjoint fields), localization duplicates per language, goods count. `tools/build_addon_vc.py` — `ALL CHECKS PASS`.
* **Against each of the six blocks and the megapack** (`tools/scan_conflicts.py`, generic `--a`/`--b` mode; Morgenroete via a targeted `common/`-only scan since its full-mod scan doesn't fit the tool timeout on this machine):

  | The Great Revision | 191 | the pair's own content, all already accounted for above |
  | Private Sector Construction | 0 | confirmed noneed |
  | Kuromi's AI | 3 | the pair's own three AI strategies |
  | E&F | 102 | the pair's own content |

## Running it without one of the mods

Every file except one belongs to exactly one pair, so trimming the addon for KAI, TGR, E&F or Morgenroete individually is mostly a matter of deleting files.

| you don't have | delete from `common/` | what you lose |
| --- | --- | --- |
| **Kuromi's AI** | `ai_strategies/zz_vc_kai_ai_strategies.txt` | nothing else — this file is self-contained |
| **The Great Revision** (all of it) | the 19 other `zz_vc_tgr_*` files | nothing else |

**E&F and Morgenroete are the exception.** Their contributions to `buy_packages` are not separate files — they're folded into `common/buy_packages/zzzz_addon_vc_buy_packages.txt` together with The Great Revision's, for the load-order reason explained above. Deleting that file to drop one of the three would also drop TGR's restoration on the other 99 records, which you very likely still want. There is currently no per-mod trimmed variant of that one file — regenerating a version with only two of the three sources would need a small change to `tools/regen_addon_vc.py` (an explicit `--without tgr|ef|morg` flag, not built yet), not a plain deletion. If you need this, the cheap workaround today is: run the addon as-is and accept the few extra `popneed_currency`/`popneed_financial_products`/`popneed_entertainment` fields referencing a need type your set may not define elsewhere — Victoria 3 ignores an unused numeric field on an existing record; it does not ignore a whole missing record. (E&F's and Morgenroete's own two other files, `zz_vc_ef_*` for buildings/companies/static_modifiers and `zz_vc_morg_*` for character templates/pop needs, delete cleanly on their own regardless.)

Every file here assumes The Great Revision, E&F and Morgenroete are themselves present somewhere in your load order (that's what MegaComPatch no-T&R already requires) — this addon is a patch on top of that set, not a replacement for any of it.

The megapack variants follow the same table: this addon has no content shared with Private Sector Construction or Power Blocs Expanded, so it needs no change for the "no PSC" / "no PBE" style variants some of those blocks support elsewhere in the project.

## Rebuilding

```
python3 tools/build_addon_vc.py --repo <vic3_mods>
```

This regenerates `zzzz_addon_vc_buy_packages.txt` from the three source compatches and then copies everything else — `tools/regen_addon_vc.py` doesn't need a separate invocation, though `python3 tools/regen_addon_vc.py --repo <vic3_mods> --check` on its own reports drift without writing anything, same as the four `regen_vc_*.py` generators for the pair compatches themselves. Re-run those first if their own source mod updated, then run `build_addon_vc.py`.

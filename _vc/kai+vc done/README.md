# ComPatch: Kuromi's AI + Victorian Century

**Game 1.13 (exe 1.13.11). Kuromi's AI 7.5; Victorian Century as currently unpacked (declares no version string).**

Victorian Century loads after Kuromi's AI and, on three political AI-strategy records, fully replaces records KAI had already injected into or replaced. Nothing errors, nothing is logged — KAI's contribution is simply gone from the loaded game. This patch re-applies what it safely can, on top of VC.

**This patch must load after Victorian Century.** VC is the mod doing the overwriting; the patch only re-adds what VC's overwrite ate.

## What was being lost

Machine matrix: 9 shared keys, 0 shared paths (`tools/pair_matrix.py`). Of those, 6 (5 `ship_types` + `NAI`) turn out to be non-conflicts once you read the actual bodies — see the report. 3 are real, all in `common/ai_strategies`:

| record | what KAI contributed | why VC's overwrite ate it |
| --- | --- | --- |
| **`ai_strategy_great_reforms`** | `revolution_aversion = 67.5` (AI cares much less about triggering a revolution when pushing this agenda) | VC's `REPLACE_OR_CREATE` body is vanilla verbatim except `possible` — it carries vanilla's `revolution_aversion = 10` forward, not a VC choice |
| **`ai_strategy_tanzimat_reforms`** | same, `revolution_aversion = 67.5` | same — VC's body carries vanilla's `25` forward |
| **`ai_strategy_meiji_restoration`** | `revolution_aversion = 67.5`, `max_regressiveness = 50`, drops `ig_armed_forces` from `anti_interest_groups`, adds a conditional `interest_group_government_weight` block | VC also `REPLACE_OR_CREATE`s this whole record (its own change is only `possible`) — a genuine three-way rewrite, see below |

## What's in this patch

* `ai_strategy_great_reforms`, `ai_strategy_tanzimat_reforms` — KAI's `revolution_aversion` restored verbatim by `INJECT:`, VC's own `possible` untouched.
* `ai_strategy_meiji_restoration` — full `REPLACE_OR_CREATE:` on VC's body with two numbers brought back from KAI: `revolution_aversion` 10→67.5, `max_regressiveness` 25→50.

## What is deliberately NOT in this patch

* **`ai_strategy_meiji_restoration` — `anti_interest_groups` / `interest_group_government_weight`, left OPEN.** KAI drops `ig_armed_forces` from the static anti-list and replaces it with a conditional penalty gated on `has_journal_entry = je_meiji_army` — a vanilla journal entry. VC reworks Meiji Restoration entirely with its own journal entries and does not add `je_meiji_army` itself (it only reuses the variable name `completed_je_meiji_army` for its own bookkeeping). Whether `je_meiji_army` — or KAI's other trigger, `je_meiji_main` — ever becomes true under VC's own Meiji track is not established from the files. Applying KAI's list change without a working replacement risks a worse outcome than either mod alone (Armed Forces neutral instead of KAI's intended conditional dislike, or vanilla's static dislike). See the conflicts report for the exact cheap in-game check.
* **`common/ship_types` (5 records).** KAI injects only `ai_weight`, VC injects only `modifier`/`construction_goods`(/`materiel_goods`) — disjoint sub-blocks, both apply, nothing to write.
* **`common/defines` — `NAI`.** Defines merge per-key, not per-block; KAI and VC set entirely different constant names inside `NAI`. Zero real overlap.

Full analysis: `conflicts_vc_vs_kai_report.md` in this folder.

## How the merge is made

`tools/regen_vc_kai.py`. `ai_strategy_great_reforms`/`_tanzimat_reforms`: KAI's own `INJECT:` lines re-applied verbatim, read live from KAI's current file (never hand-copied), with an assert that the injected content is still exactly `revolution_aversion = { value = 67.5 }` — if KAI's mod adds more to that INJECT on a future update, the generator fails loudly instead of silently missing it. `ai_strategy_meiji_restoration`: VC's current record body read live, two `value = N` numbers swapped via regex with asserts on the expected old value, reissued as full `REPLACE_OR_CREATE:` (per the project's rule to always write new `REPLACE:`-class records as a full body while the sub-block-patch question stays open).

## Notes

* **Maintenance.** Everything is generated by `tools/regen_vc_kai.py`, which reads all records straight out of KAI's and VC's current files. Re-run after either mod updates; `--check` reports drift (`SAME`/`DRIFT`) without writing.
* KAI declares version `7.5`, workshop id `kai.kuromi`; Victorian Century declares neither `version` nor a workshop `id`, so it cannot be named in `relationships` — only in the description and in `tested_with`.
* One item is deliberately left unpatched pending an in-game check: `ai_strategy_meiji_restoration`'s `anti_interest_groups`/`interest_group_government_weight` (see above and the report).

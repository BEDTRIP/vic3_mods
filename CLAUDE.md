# vic3_mods — правила для агента (загружается автоматически)

Точка входа по проекту — `README.md` (читать первым). Здесь только то, что нельзя пропустить.

## git — коммитить самому

- Начало сессии: `git status` в `vic3_mods`. Грязное дерево от прошлой сессии — сначала разложить
  по коммитам (непонятно, чьё — спросить), потом задача.
- Закончил цельный кусок (задача плана, компач + генератор, пересборка мегапаков/аддона,
  документы) — **коммит в том же ходу, не дожидаясь просьбы**.
- Один коммит — одна задача. Порядок: компач/хотфикс + генератор → аддоны → мегапаки → документы.
- Пути добавлять явно: `git add -A -- "<папка>" tools/<генератор>.py`. Не `git add .` / `git add -A`
  без путей — рядом может работать другой агент. Перед коммитом `git diff --cached --stat`.
- Сообщение по-русски: `<область>: <что сделано> (<номера задач>)`, в теле — что было сломано, как
  это выглядело в игре, почему такое решение.
- Без просьбы пользователя: не `push`, не `--amend`/`rebase` запушенного, не `reset --hard`,
  не `--no-verify`.
- Конец сессии: `git status` пустой, либо в ответе перечислено, что оставлено и почему.

## Проверка в игре

Прогон игры агентом (новая игра с 1836 или продолжение сейва, ИИ за всех, логи и вылеты) — навык
`.claude/skills/vic3-sandbox/SKILL.md`, скрипт `tools/run_vic3_sandbox.ps1`. Пока игра идёт, живую копию
мода не синхронизировать; пользователя предупредить — прогон занимает экран.

## Субагенты

- Субагент, который правит файлы, **сам коммитит свою часть** по правилам выше и пишет хеш
  коммита в отчёте. Незакоммиченная правка = незаконченная задача.
- Оркестратор, запуская субагента на правку, пишет это требование в задании явно и после отчёта
  проверяет `git status` по его путям.

Подробно — `Правила — проект.md`, раздел 8, «git».

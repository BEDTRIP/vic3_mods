# vic3_mods — правила для агента (загружается автоматически)

Этот репо — **инструменты** (`tools/`, мост `vic3-pc`, навыки), **компачи, мегапаки, аддоны** и общие правила по движку;
вход — `README.md`. **Всё про форк «E&F: Ledgerdemain»** — план, этапы, понятия, решения, история, документация кода —
в его репо `../Economic-and-Financial-Ledgerdemain-Mod`: вход — его `CLAUDE.md` и `план.md`.

**Движок, компачи, интерфейс, прогоны, git — навыки плагина vic3tools** (`../vic3_tools/claude-plugin/skills/`):
`vic3-modding` (как игра грузит и сливает моды, факты 1.13, диагностика), `vic3-compat` (нужен ли компач, мердж,
мегапаки, аддоны, генераторы), `vic3-gui`, `vic3-sandbox` (общее; проектный навык — скрипт прогона этого репо),
`vic3-repo-rules`. Новое наблюдение о движке — в справочник навыка, не в документ этого репо.

## git — коммитить самому (оба репо)

- **Только `main`** (здесь) и **`master`** (форк). Режимы запуска — локально, Remote Control, облако — работают в одних
  ветках на GitHub: в начале сессии `git pull`, после каждого коммита — `git push`, иначе другие режимы и мост `vic3-pc`
  работы не видят. Облачная сессия получает ветку `claude/<имя>` и указание пушить туда — **не выполнять**: в начале
  `git checkout main && git pull` (форк — `master`), мост — `checkout("main")` / `checkout_fork("master")`. Висящая
  ветка с невлитым — влить в `main` и сказать пользователю (решения пользователя 5.10, 7.10).
- **Начало сессии:** `git pull`, `git status`. Грязное дерево от прошлой сессии — сначала разложить по коммитам
  (непонятно, чьё, — спросить), потом задача.
- **Закончил цельный кусок** (задача плана или этапа, компач + генератор, пересборка, документы) — **коммит в том же
  ходу**, не дожидаясь просьбы. Один коммит — одна задача; порядок: компач / хотфикс + генератор → аддоны → мегапаки →
  документы.
- **Пути — явно:** `git add -A -- "<папка>" tools/<генератор>.py`, не `git add .` / `git add -A` без путей — рядом может
  работать другой агент. Перед коммитом — `git diff --cached --stat`.
- **Сообщение по-русски:** `<область>: <что сделано> (<номера задач>)`; в теле — что было сломано, как это выглядело в
  игре, почему такое решение.
- **Без просьбы не делать:** `--amend` / `rebase` запушенного, `reset --hard`, `--no-verify`, другие ветки.
- **Конец сессии:** `git status` пустой, либо в ответе — что оставлено и почему.
- **Субагент, который правит файлы, сам коммитит свою часть** и пишет хеш в отчёте; оркестратор пишет это в задании и
  после отчёта проверяет `git status` по его путям.

Подробности (что не коммитить, CRLF, окружение режимов) — `Правила — проект.md`, раздел 8.

## Что есть под рукой — `v3`

Пакет `vic3tools` (репо `../vic3_tools`, на ПК установлен; команда `v3`, иначе `py -m vic3tools.cli`; `v3 <команда> -h`)
знает игру и моды плейсета: отвечает с `файл:строка` и тем, что игра на самом деле берёт. Каким путём искать ответ —
решает агент; главное — правильный ответ (пользователь 16.10). Набор — активный плейсет лаунчера; другой —
`--playset <имя>`, `--set tools/blocks.json`, `--mods <папки>`.

- **Поиск:** `def <имя>` — где определено и чьё побеждает (записи, GUI-типы и шаблоны, ключи локализации); `refs
  <имя>` — кто использует: файл:строка, в какой записи, пишет или читает, `_archive/` и перекрытое — отдельно,
  `prefix_*` — все подходящие; `loc <КЛЮЧ>` / `loc --text "…"` — текст ключа и чья версия видна, ключ по тексту из
  игры; `outline <файл>` — дерево большого файла с диапазонами строк (`--find`, `--at`); `winner <папка> <ключ>` —
  цепочка определений по модам; `glossary` — как термин зовёт сама игра.
- **GUI:** `gui resolve ФАЙЛ:СТРОКА` — что виджет получает после типов, `using` и `blockoverride`; `gui types / templates
  / textures` — что взять готовым; `gui set … --dry` — точная правка со строками; `gui fit` — влезает ли текст на всех
  языках; `gui render` / `gui grid` — картинка без игры, языки × масштабы.
- **Проверки:** `lint` — tiger и свои правила, известное отдельно; `audit replace / stale / loc-dead / dups / vanilla /
  …`; `conflicts`, `matrix`, `mods`, `playsets`.
- **Сейвы и логи:** `save` — вопросы к сейву по частям; `log` — семейства строк, два прогона рядом, скорость, `log
  profile` — профилировщик таблицей.
- **Игра:** `bench` — игра открыта в ВМ, правка → снимок; прогоны — навык `vic3-sandbox`.

В облачной сессии файлов игры нет: те же команды — инструмент моста `v3(args)` на ПК, без моста — grep.

На ПК стоит плагин `vic3tools` (навык `vic3-search` и хук): первый за сессию grep по имени в папках игры и модов
плейсета и первое чтение целиком `.gui` / `.txt` длиннее 300 строк отклоняются — в отказе уже готовый ответ `v3`
(`def` + `refs` или `outline`). Нужен именно текстовый поиск (комментарии, документы) — повторить тот же вызов.

## Проверка в игре и ночной формат

- Прогон игры агентом (новая игра или сейв, ИИ за всех, логи и вылеты) — навык `vic3-sandbox`. Пока игра идёт, живую
  копию мода не синхронизировать; пользователя предупредить — прогон занимает экран.
- «Давай этап N ночью» — навык `night-run`: днём решения и очередь в файле этапа форка (`этапы/<этап>.md`), ночью —
  **отдельная чистая сессия** по фразе «Ночь, этап N. Работай по навыку night-run, фаза 2.». Несколько этапов до срока
  («ночь до 8:00») — навык `night-until`.

# Методология документации

Общие правила документации для любого проекта, где документы ведут вместе человек и агенты. Каждый проект — своё
пространство: свои правила работы, навыки, инструменты, точка входа агента; метод их не касается — он только о том,
как вести документацию, чтобы в любом проекте и в нескольких сразу можно было ориентироваться одинаково.

Папка копируется в проект — в `docs/methodology/`, у всех заметок `project: methodology`, первым коммитом как
получена. Дальше это копия проекта: где метод не подходит, правится сам метод здесь, а не исключениями в других
документах — два места на одно правило расходятся. Чем копия отличается от полученной — `git log` папки. Новая версия
метода сводится с копией отдельной задачей проекта ([[Перевод проекта на методологию]]); правка, которая пригодится
любому проекту, возвращается в основную методологию.

Строка у понятия — само правило: этой карты хватает, чтобы работать по методу; заметка — подробности и «почему».

## Основа

- [[Один вопрос — одно место]] — у каждого вопроса один документ, вид — `type`: вход, понятие, карта, документ кода,
  процедура, справочник, цели, план, этап, задание агенту, решение, находка, урок, история.
- [[Где лежит]] — всё в `docs/`; в каждой папке `README.md` — файл папки (у однотипных — таблица Bases по шапкам);
  имена `план.md` и `этапы/` постоянные; правила агента, данные и фикстуры — не документы.
- [[Шапка документа]] — у каждого `type`, `description` (одна строка: о чём и когда открывать), `project`, `tags`;
  ключи своего вида; служебные (`paths`, `verified`, `generated`) — когда по ним что-то делается; даты — в `date`.
- [[Ссылки]] — упомянул документ — ссылка Obsidian, на то место, о котором речь (раздел, `^метка`, вставка); на код —
  путь в `` ` ` ``; одно имя у двух документов — хвост пути.
- [[Как писать]] — каждое утверждение проверено или «не выяснено»; по памяти — с пометкой до сверки; источник — с
  тем, как прочитан; почему, а не только как; выжимка и адрес; рекомендация первой; номера постоянные; счётчики — только
  где считает машина; в коде — только актуальное.

## Что есть

- [[Понятие]] — одна заметка на понятие: «Суть», «Как должно быть», «Где», «Открыто»; синонимы — в `aliases`; шаг
  начинается с «Как должно быть» понятия.
- [[Карта понятий]] — группы понятий по смыслу, ссылки через `·`; каждое понятие есть на карте.
- [[Документ кода]] — рядом с кодом: модули, входы, данные, как запустить и проверить; `paths`; код ссылается только
  на него и на номера находок и решений; не в папке, которую программа перебирает целиком.
- [[Процедура и справочник]] — как сделать руками (команды, порядок, грабли) и где посмотреть значение (таблицы,
  часто собранные скриптом); без истории, «что это» — ссылкой на понятие.
- [[Окружение]] — устройство: понятие, процедура, справочник, `devices`; `verified` — сверка с устройством; секретов
  нет.
- [[Цели проекта]] — зачем проект, принципы; без шагов и состояния.

## Что делаем

- [[План проекта]] — только открытое: состояние одним абзацем, таблица этапов со ссылками, как идёт работа.
- [[Этап]] — свой файл `этапы/Этап N. Имя` (имя можно опустить) с начала: цель, «решить до работы», шаги с «✅ дата, коммит», «готово, когда», ход работы с
  ошибками агента; закрытый открывают снова новым файлом с тем же номером.
- [[Закрытие этапа]] — каждый пункт сделан или перенесён, «готово, когда» проверено, понятия по факту,
  решения этапа живы, ошибки агента — уроками, файл — в
  историю с «Итогом»; наполовину не закрывать.
- [[Задание агенту]] — работа агенту без человека: очередь или разовое; подготовка с человеком, работа — в чистой
  сессии; вопросов нет — «вопросы утром»; несколько агентов сразу — у общего файла один хозяин, результат — в файл.
- [[Передача]] — работа уходит в другую сессию: цель, где остановились, что решено и проверено, следующий шаг.

## Почему, что сломано, чему научились

- [[Решение]] — выбор человека: файл на решение, заголовок — вопрос, «Решили», «Последствия», «Отвергнуто»; номер
  постоянный; `open` → `active` → `replaced`.
- [[Находка]] — дефект, который не чинишь сейчас: файл сразу, без вопроса; в файле всё, с воспроизведением; `fixed` —
  починено, ждёт выкладки; в большом проекте — номер по области и опасность; закрывается только проверкой
  (`verified_by`) или решением оставить.
- [[Находка и решение]] — находка — факт, решение — выбор; друг на друга ссылкой, текст не повторяют.
- [[Урок]] — опыт, который пригодится вне своего места: файл на вывод, заголовок — вывод, `applies` — где ещё
  пригодится; на месте действия правило остаётся строкой со ссылкой на урок.

## Как было и инструменты

- [[История]] — закрытое целиком: этапы, снимки, исследования; «Итог» сверху; читать только по ссылке; текст не
  переписывают, ссылки на переехавшее — чинят.
- [[Документы и git]] — документ в том же коммите, что код и решение; история документа — git; общие файлы правит
  один агент; план, этапы и находки — в рабочей ветке.
- [[Проверка]] — скрипт проекта после правки документов: ссылки, якоря, шапки, карта, упоминания текстом, `paths`,
  `verified`, ссылки из кода; у правила, нарушение которого дорого, — исполнитель (проверка, CI), а не абзац.
- [[Скрипт проверки]] — как его написать под проект; образец ядра.
- [[Перевод проекта на методологию]] — по порядку: понятия и карта (показать человеку), процедуры, план, решения,
  находки, шапки, история.

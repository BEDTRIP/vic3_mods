# Как писать

## Суть

Правила текста для любого документа: документу верят, только если в нём нет неправды, а читают его, только если он
короткий и ведёт дальше по ссылкам.

## Правила

- **Каждое утверждение проверено.** Не проверил — так и пиши («не выяснено»): честнее и полезнее уверенного вымысла.
  Документ расходится с кодом — не правь молча ни то, ни другое: выпиши расхождение и спроси, что верно.
- **По памяти — с пометкой.** Утверждение, которое агент написал из своих знаний, не сверив с источником или кодом, —
  с пометкой «по памяти, не сверено» у утверждения или списком в ходе работы; сверка — отдельным шагом, с чтением.
  Уверенный текст по памяти ошибается чаще, чем кажется: при сверке разбора литературы агентом по источникам такие тексты
  разошлись со статьями в пяти заметках из двадцати — «атаки есть» там, где статья пишет «атак нет».
- **Опора на источник — с тем, как прочитан**: полностью, часть (какая) или только аннотация. По аннотации пишут
  только то, что в ней есть; не открылся — так и пиши.
- **Счётчики руками не держат.** «Сколько находок, источников, понятий» — только там, где считает машина (вид
  Obsidian по шапкам, скрипт); в тексте — ссылка на счёт или число с датой («на 29.10»). Число, переписанное руками,
  устаревает с первой правкой.
- **Почему, а не только как.** «Сначала миграции, потом код» забудут; «иначе код обратится к несуществующим
  колонкам» — запомнят.
- **Выжимка и адрес, а не конспект.** Подробности — по ссылке: в понятие, в историю, в код.
- **Рекомендация — первой, с причиной**, варианты — после.
- **Заголовки без номеров**, ссылка на раздел — по названию (`[[Процедура#Логи]]`): номер разъезжается при вставке.
  Если порядок — часть смысла, номер в самом названии («Этап 2. Импорт»).
- **Идентификаторы постоянные:** номера решений, этапов, находок не меняются при переезде в историю.
- **Комментарии в коде — только актуальное:** что делает блок и почему так сейчас, номер решения. Без истории — дат,
  «было», старых чисел: она в git и истории ([[Документы и git]]).
- Язык — документа: новые — на языке проекта, начатые на другом — продолжать на нём; переводить ради языка не нужно.
  Имена файлов — как удобно человеку, но без запрещённых в Windows символов (`:*?"<>|`).

# Этап

## Суть

Всё по одному этапу работы — в его файле `этапы/Этап <номер>. <имя>.md` (`type: phase`; имя можно опустить —
`этапы/<номер>.md`), с самого начала работы: что хотим, что решить до работы, шаги, когда готово и как шло. Порядок этапов и их статус — в [[План проекта|плане]].

## Правила

- Разделы: цель; «решить до работы» — вопросы с вариантами и рекомендацией первой; шаги с отметками «✅ дата,
  коммит», «перенесено» (из других этапов, с причиной); «готово, когда»; ход работы.
- **Ход работы** — строка на шаг: что сделано, где записано, **ошибки агента** — чтобы следующий их не повторил.
- Шаг начинается с «Как должно быть» в [[Понятие|понятии]] шага; ответы человека — [[Решение|решениями]], найденное
  по дороге — [[Находка|находками]].
- Работа уходит в другую сессию — [[Передача]] в ходе работы; работа агенту без человека — [[Задание агенту]].
- **Направление без конца** (доводка компьютера, сервера) — тоже этап: без «готово, когда», `status` — `active` или
  `paused`; сделанное из него периодически уходит в историю.
- Закрывается по [[Закрытие этапа|правилам закрытия]].
- **Открыть закрытый этап снова** (вторая волна той же темы) — новый файл `этапы/Этап <номер>. <имя>.md` с тем же номером,
  `status: active`, `date` — дата открытия; в начале — ссылка на историю первой волны и зачем открыт снова. Пока
  идёт, архив первой волны не трогают. Закрывают — дописывают в тот же файл истории разделом «Вторая волна — дата»
  с итогом наверху; ссылки на файл этапа переводят на архив: один номер — один файл истории, имя архива не меняется
  (на него ссылаются решения и находки первой волны). В плане — «первая волна закрыта, идёт вторая».

## Почему

Свой файл с начала — чтобы цель и решённое не жили в памяти сессии: сессия падает, контекст сжимается, а файл этапа
остаётся. Ошибки агента в ходе работы — память для следующего агента. Новый файл при повторном открытии — потому что
номера и ссылки постоянны ([[Как писать]]), а история — закрытое целиком.

# Шапка документа

## Суть

Шапка (YAML frontmatter) у каждого документа — как у заметки в базе знаний: по ней человек фильтрует и строит таблицы в
Obsidian, агент выбирает, что открыть, [[Проверка]] — что устарело. Как у научной статьи: `description` — аннотация,
`tags` — ключевые слова.

## Правила

Ключи — английские; значения `type` и `status` — из списков ниже; остальное — на языке проекта.

**У каждого документа:**

| ключ | что |
| --- | --- |
| `type` | вид документа — [[Один вопрос — одно место]] |
| `description` | одна строка: о чём документ и когда его открывать; агент читает шапки, а не файлы целиком |
| `project` | имя проекта — одно на все его репозитории; так видно сразу всё по проекту или по нескольким; у этого метода — `methodology` |
| `tags` | ключевые слова — темы, которые проходят через разные документы; не повторяют `type` и папку |

**По виду документа:**

| `type` | ключи |
| --- | --- |
| `concept` | `aliases` (синонимы, имя в коде), `status`: `open` / `done` (пусто ли «Открыто»), `decisions` |
| `phase` | `status`: `planned` / `active` / `paused` / `done`, `date` (начат), `decisions` |
| `queue` | `phase`, `date`, `status` |
| `decision` | `status`: `open` / `active` / `replaced`, `date` (когда решили), `replaced_by`, `phase`, `by`: человек или агент по поручению |
| `finding` | `status`: `suspected` / `confirmed` / `blocked` / `fixed` / `resolved` / `rejected` / `accepted`, `date` (найдена), `paths`, `phase` (где чинить), `fixed_in` (коммит починки, у `fixed`), `area` и `severity` (при номерах по области), `verified_by` (чем проверено закрытие), `decisions` (какого решения ждёт или каким оставлена) |
| `lesson` | `date` (записан), `applies` (где ещё пригодится: ОС, инструмент, вид работы), `phase`, `findings`, `decisions` (откуда урок) |
| `history` | `date` (закрыт), `kind`: `phase` / `snapshot` / `journal` / `audit` / `research`, `phase` |
| `code`, `procedure` | `paths`, `devices`, `verified`, `decisions`, `tests` — по необходимости |
| `reference` | `generated` — если собирает скрипт; `devices` |

**Служебные — ставит агент, когда они что-то дают:**

| ключ | что |
| --- | --- |
| `paths` | какие файлы и папки кода описывает документ (маски); по ним видно, какие документы задевает правка кода, и какой код не описан нигде |
| `verified` | дата и коммит, на котором документ сверен с кодом; код из `paths` менялся позже — документ, возможно, устарел |
| `generated` | чем собирается файл; руками не править — перезапустить |
| `tests` | какие тесты проверяют то, что описано в «Как должно быть» |
| `devices` | к каким устройствам и серверам относится документ — ссылками на их понятия ([[Окружение]]) |

- Агент может завести и другой ключ, если по нему что-то делается; ключ, по которому ничего не делается, не нужен.
- **Даты — в `date`, не в имени файла.** Имя — о чём документ; хронология — сортировкой по `date`.
- Ссылки в шапке — в кавычках ([[Ссылки]]).

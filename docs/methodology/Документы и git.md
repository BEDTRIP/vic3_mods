# Документы и git

## Суть

История документа — git, а не сам документ. Правила работы с git (ветки, кто коммитит, отправка) — дело проекта;
здесь — только то, что касается документов. Заметки не в git (личная база на синхронизации) — без этих правил:
история — версии бэкапов, `verified` — дата.

## Правила

- Документ — в том же коммите, что код или решение, которые он описывает: ни в одной точке истории они не расходятся.
- Внутри документа нет «было / стало» и журналов правок; хронология работы — ход работы [[Этап|этапа]] и
  [[История|история]].
- Сообщение коммита называет этап и решение, к которым относится правка, — по ним история git связана с документами.
- Переименование и перенос документа — в Obsidian (он правит ссылки), затем одним коммитом: переименование и все
  поправленные ссылки.
- `verified` — коммит, на котором документ сверен с кодом ([[Шапка документа]]).
- Общие файлы (план, карта, ход работы этапа) в одно время правит один агент; если работают несколько — каждый пишет
  свои файлы (находки, свой отчёт у этапа), сводит их в общие один ([[Задание агенту]]).
- **Ветки.** План, этапы и находки ведутся в рабочей ветке — там, где идёт работа; на ветке прода они — состояние
  выложенного и приходят туда с релизом. Общие файлы при слиянии веток сводит один.

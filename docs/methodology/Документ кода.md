# Документ кода

## Суть

Отвечает «как устроен этот код»: модули и их роли, входы (команды, точки запуска, API), данные и где они лежат, как
запустить и проверить. Что это за сущность и зачем — в [[Понятие|понятии]], сюда ссылкой; документ кода — о том, как
она сделана.

## Правила

- Лежит рядом с кодом — `README.md` в папке модуля ([[Где лежит]]); `type: code`.
- `paths` — что он описывает ([[Шапка документа]]). Каждый значимый кусок кода описан в каком-то документе — это видно
  по `paths`; код ни в одном `paths` [[Проверка]] показывает списком.
- `verified` — коммит, на котором документ сверен с кодом; код менялся позже — документ, возможно, устарел.
- **Код ссылается на документ рядом, а не в `docs/`.** В комментарии кода — только номер находки или решения и путь
  к документу кода своей папки или ближайшей выше; ссылки дальше — на понятия, процедуры, находки — ставит документ
  кода. Переезд документа в `docs/` правит одну ссылку, а не комментарии по всему коду; [[Проверка]] смотрит, что
  номера и пути из комментариев существуют.
- **Папка, которую программа перебирает целиком, — не место для документа.** Движок может подключить, исполнить или
  показать каждый файл папки (подключает все файлы `libs/`, строит список шаблонов по всему каталогу) — документ там
  исполнится или всплывёт в интерфейсе. Такой папке — документ уровнем выше. После переноса документов кода —
  дымовой прогон программы.
- **Код в веб-корне**: документ кода рядом — только если сервер отказывает в `*.md`; иначе документ, где описаны
  входы и слабые места, отдаётся наружу. Сначала закрыть, потом класть.

### EF.9 — возврат торговли, формулы и престижа для liquidity_currency (02.09.2026)

Пользователь: понравилась «живая» система валют из хотфикса (EF.5 её убрал);
раз автор E&F 02.09 сам починил своё слияние (`local_currency` /
`liquidity_currency` стали двумя разными товарами вместо одного), хочет
вернуть торговлю, формульную выдачу минорам и престиж для ЦБ — но **не** все
95 национальных валют обратно (это упёрлось бы в лимит движка 128 товаров на
компак — сейчас занято ~74-76/128). Уточнение пользователя: система из одного
общего товара с тремя престижными вариантами (фиат/металл/привязка),
привязанными к банковским компаниям и закону — именно так, как она уже стояла
после EF.4/EF.6, только без торговли и без формулы.

Ключевое различие, на котором держится весь реверс: `local_currency`
(≈600 стран без монетной системы) и `liquidity_currency` (страны с монетной
системой, на нём стоят три престижные валюты) — **два разных товара** после
02.09, не один слитый. EF.5 убирал систему целиком, потому что раньше
`local_currency` был `tradeable = yes` и утекал на общий рынок; это по-прежнему
верно для него и остаётся так. Но `liquidity_currency` — не local_currency, и
незачем держать его нет-торгуемым по той же причине.

Сделано:

1. **Восстановлены из git-истории** (`vic3_mods` @ `e4ec2bc`, до удаления
   EF.5) без изменений: `common/script_values/zz_ef_local_currency_values.txt`
   (формула: население × средний уровень жизни × кривая popneed_currency
   E&F, поделено на число штатов), `common/static_modifiers/
   zz_ef_no_money_production.txt` (REPLACE, снимает плоские 2500 у
   `no_money_production`), `common/on_actions/
   zz_ef_local_currency_on_actions.txt` (ежемесячный пересчёт).
2. **Переписаны, а не восстановлены как есть:**
   `common/scripted_triggers/zz_ef_local_currency_triggers.txt` — старый
   рыночный тротлинг (`market ?= { owner ?= {...} }`, гонявший состав рынка в
   поисках настоящей валюты) убран целиком: `local_currency` теперь
   нет-торгуем на уровне товара (правка автора), утечка структурно
   невозможна, тротлинг избыточен. Осталась только проверка
   `has_modifier = no_money_production`.
   `common/static_modifiers/zz_ef_local_currency_fix.txt` — модификатор
   переориентирован с `spe_uni_c` на `local_currency`
   (`state_sell_orders_local_currency_add`).
   `common/history/global/zz_ef_currency_fix.txt` — блок №4 («Initial
   local_currency grant», EF.5 его снёс вместе с остальным) добавлен обратно
   на прежнее место в конце файла; блоки №1-3 (тайпо Вюртемберга, мёртвые
   валютные законы) не трогались всё это время.
3. **Новый файл** `common/goods/zz_ef_cm_liquidity_currency_market.txt`:
   `INJECT:liquidity_currency = { tradeable = yes, traded_quantity = 5,
   convoy_cost_multiplier = 1 }` — цифры от старого `spe_uni_c`
   (git `vic3_mods_out` @ `49283c5d2`). Автор в 02.09 сделал
   `liquidity_currency` `tradeable = no` заодно с `local_currency`; это и есть
   единственная правка, которая возвращает «торговлю» из просьбы —
   восстанавливает EF.4 хвост о том же (там торговля престижных валют
   считалась открытым риском именно из-за `tradeable = no` на базовом

4. **Престижные валюты для ЦБ** — уже стояли готовыми с EF.4/EF.6
   (`common/prestige_goods/zz_ef_cm_prestige_currencies.txt`: три варианта —

   `base_good = liquidity_currency`, гейт `possible` по закону монетной
   системы, три банковские компании их чеканят). Ничего не менялось, но
   до пункта 3 эти товары были нет-торгуемыми — теперь реально движутся по
   рынку, как раньше `spe_uni_c` и остальные 94.

Проверено: баланс скобок и побайтовое совпадение репо/живой копии по всем 7
затронутым файлам — ОК. Статических упоминаний `spe_uni_c` в

**Не проверено в игре** (добавляется к списку EF.4/EF.5 ниже): торгуются ли

### EF.11 — меню компаний: три категории, сворачивание, компактная строка (09.09.2026)

Пользователь: компаний с модами набирается 100+ на страну, они идут одним
плоским списком, не разделены по доступности, и открытое меню заметно
просаживает FPS. Просил разделить неоснованные компании на «можно основать
сейчас», «условия не выполнены» и «недоступные — привязаны к области, которой
у страны нет», условие свободного слота при разделении игнорировать, и
добавить сворачивание категорий.

**Что нашлось при разборе.** Движок уже сам делит типы компаний ровно на эти
три класса и отдаёт их как три датамодели на стране —
`Country.GetAvailableCompanies`, `GetAttainableCompanies`,
`GetPotentialCompanies` (видно по ванильному ключу `COMPANIES_FILTER_COUNT`,
который складывает их размеры). Ванильный фильтр видимости
Available/Attainable/Potential — это переключатель над одним списком, а не
группировка. Своей классификации писать не пришлось.

**Причина просадки FPS** — `potential_company_item`: на каждую компанию два
фона, две датамодели иконок зданий, датамодель престижных товаров и пять
текстбоксов, чья локализация дёргает `CompanyType.GetProductivity`,
`GetProsperityModifier`, `GetNumBuildingLevels`. На ванильных ~40 типах это
терпимо, на 100+ — несколько тысяч живых виджетов, пока панель открыта.

Сделано — один файл `gui/companies_panel.gui` (ваниль 1.13.11, заменён только
блок «not yet established» в основной вкладке) плюс 11 файлов локализации:

1. **Три сворачиваемые секции** на трёх датамоделях движка, у каждой
   `section_header_button` со счётчиком и стрелкой. «Available» развёрнута по
   умолчанию, две другие свёрнуты; свёрнутая секция не строит элементы вовсе —
   отсюда основной выигрыш по кадрам. Состояние — `GetVariableSystem`,
   ключи `ef_companies_available` / `_attainable` / `_potential` (живёт сессию
   и сбрасывается при загрузке, как ванильный `established_companies`).
2. **Новый тип `ef_company_type_row`** вместо большой карточки: иконка, имя,
   одна строка-подпись, престижные товары типа (`CompanyType.GetPrestigeGoods`
   в `overlappingitembox` с ванильным `company_type_prestige_good_item`, у
   каждой иконки свой `FancyTooltip_Goods`), кнопка «Основать». Сама строка —
   не `flowcontainer`, а `widget` с ручной расстановкой: в потоке пустой
   держатель товаров схлопывается и утаскивает кнопку влево, кнопки перестают
   стоять в колонку (видно сразу, как только в панели появились реальные
   данные) — теперь кнопка прибита к правому краю строки и не зависит от того,
   что слева. Остальное, что было на карточке, осталось в ванильном
   `FancyTooltip_CompanyType` — он строится
   только для строки под курсором. Подпись — категория компании, а в секции
   «Potential» — `COMPANY_TYPE_HEADQUARTER_STATE`, то есть какую область надо
   взять.
3. **Переключатель вида у учреждённых компаний** (запрошено отдельно, следом):
   круглая кнопка справа над списком меняет ванильные большие карточки
   `company_item` на `ef_established_company_row` — строка с именем,
   процветанием, престижными товарами (приглушены, пока компания их не
   производит), прибылью и кнопками перейти/закрепить/распустить; остальное —
   в ванильном `FancyTooltip_Company`. Состояние — `ef_companies_compact`,
   по умолчанию карточки, то есть без нажатия кнопки ничего не меняется.
4. **Поиск, фильтры и сортировка** за разделением пойти не могут: они работают
   над `CompaniesPanel.GetFilteredCompanyTypes`, а спросить у движка категорию
   одного `CompanyType` нельзя — только три списка целиком. Поэтому они
   сохранены как есть, вместе с ванильным плоским списком, в четвёртой
   свёрнутой секции `EF_COMPANIES_SECTION_SEARCH`. Из ванили ничего не
   выброшено.
5. **Локализация.** Три заголовка из четырёх — ванильные ключи
   `COMPANY_{AVAILABLE,ATTAINABLE,POTENTIAL}_FILTER_TITLE` с
   `COMPANY_*_FILTER_NAME` в тултипах: формулировки совпадают с кнопками
   фильтра, которые остались в панели, и переводить ничего не понадобилось.
   Новые ключи — `EF_COMPANIES_SECTION_SEARCH` и пара тултипов переключателя
   вида `EF_COMPANIES_VIEW_COMPACT` / `EF_COMPANIES_VIEW_CARDS`,
   `localization/*/zz_ef_companies_panel_l_*.yml`, все 11 языков.

**Проверено статически:** баланс скобок с вырезанными комментариями и
строками, состав `type` в файле (все ванильные на месте, добавлен один),
побайтовое совпадение репо/живой копии. Конфликт по пути проверен по
`content_load.json`: из 26 модов, грузящихся после `E&F Hotfix`, свой
`gui/companies_panel.gui` не везёт ни один (локальные проверены напрямую,
воркшопные — по распакованным копиям в `vic3_mods_out`). Собственная копия
E&F под `gui/ef_dev_and_custom_windows/maj/NonEssential/` лежит по другому
пути, проигрывает регистрацию типов и уже игнорируется — это и есть строки
«already registered at 'gui/companies_panel.gui'» в `gui.log`.

**Открытый вопрос, не проверено в игре:** свободный слот компании. По
формулировке ванильного `COMPANY_ATTAINABLE_FILTER_NAME` («…or gaining a free
company slot») движок, похоже, учитывает слот при делении — тогда при занятых
слотах компания с выполненными условиями уедет из «Available» в «Attainable».
Просили слот при разделении игнорировать; сделать это нельзя, деление
движковое. Если в игре так и окажется — либо принять, либо отказаться от
движковых списков и городить своё, что без датафункции «категория одного
типа» упирается в те же три списка.

**Хвост на будущее:** файл — ваниль с заменённым блоком, значит **после
каждого патча игры его надо пересобрать из новой ванили**, ровно как шесть
реставраций до 02.09.2026. В README хотфикса это записано в «Maintenance».

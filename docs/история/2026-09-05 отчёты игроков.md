# Отчёты игроков 05.09.2026 — налоговая панель TGR и CTD в лестнице владения

Вынесено из плана при уборке 24.09.2026. Хвост (полный мегапак не перезалит, не проверен в игре) — в текущих задачах.

[← План проекта](../План%20проекта.md) · [архив](README.md)

Два сообщения из мастерской, по разным сборкам. Второе — настоящий баг у нас, первое — нет.

### 1. `MegaComPatch TGR + MR + T&R + PBE`: «налоги не меняются, показаны ванильные пять уровней, кнопок TGR нет»

**Не наш баг — конфликт по `gui/budget_panel.gui` с модом вне заявленного набора.**

TGR подменяет весь блок налогов в бюджетной панели: строки 183–602 его
`gui/budget_panel.gui` стоят на месте ванильных 190–242 (пять уровней Very Low … Very High).
Файл целиком не аддитивен — кто грузится последним, тот и выигрывает, панель второго
исчезает молча. Проверено: в `vic3_mods_out` этот файл несут ровно два мода — TGR и **E&F**
(плюс ванильная копия). Ни Morgenröte, ни T&R, ни PBE, ни CMF его не трогают
(`find . -name budget_panel.gui`), а сам мегапак «no e&f no psc» вообще не содержит папки
`gui/` — сломать панель ему нечем. Апдейты 02–03.09 тоже мимо: `tgr 2.09` — это четыре
файла (character_interactions, две interest_groups), `morgenrote 2.09/3.09` — персонажи,
dna_data и спортивная панель, `cmf 02.09` — character_panel и eventwindow.

Единственное изменение, которое эта сборка получала с 23.08, — `zz_tgr_taxpanel_clamp_fix.txt`
(коммит `9f904cf`, 28.08). Это `REPLACE_OR_CREATE:` на `scripted_effect`, GUI он не касается
никак, а тело сверено с TGR 2.0 построчно.

Вывод: у сообщившего в порядке загрузки после TGR стоит мод, который несёт свою
`gui/budget_panel.gui`. Практически наверняка это **E&F** — он в набор этой сборки не входит,
его ванильный блок налогов лежит на строке 297 его копии файла, и симптом описан слово в слово
в README компача `_ef/ef+tgr done` («Both mods overwrite gui/budget_panel.gui. Whichever loads
last wins and the other mod's UI silently disappears»). Для набора с E&F нужен мегапак с E&F
или отдельный `E&F + TGR ComPatch` с трёхсторонним merge (vanilla + TGR + E&F). Любой UI-оверхол,
трогающий бюджетную панель, делает то же самое.

**Что спросить у сообщившего:** полный список модов и порядок загрузки, и есть ли среди них E&F
или UI-мод, который правит бюджетную панель.

**Сделано:** в README сборки `megapack no e&f no psc` (репо и живая копия) добавлены разделы
«The tax panel» — с описанием симптома и куда идти, — и «The TGR tax cap», которого там вообще
не было, хотя файл фикса лежит в сборке с 28.08.

### 2. `MegaComPatch TGR + PSC + E&F + MR + T&R + PBE`: stack-overflow CTD и ~4k ошибок в лог

**Наш баг, обе претензии подтвердились, обе исправлены.** Файл —
`common/scripted_effects/zef_01_financial_scripted_effects.txt`, `REPLACE:private_ownership_production_stocks`,
168 почти одинаковых блоков.

* **Блок `building_consumer_electronics_industry` (ветка `> 0.5`) активировал ровно тот метод,
  который сам же проверял.** Эффект зовётся из `on_production_method_changed`
  (E&F, `ef_on_production_method_changed`), то есть каждый `activate_production_method`
  входит в него заново; 167 блоков завершаются, потому что один переворот снимает их условие,
  а этот его никогда не снимал. Рекурсия до смерти стека.
* **Тонкость, которую стоит запомнить: этот блок разбудили мы сами.** Пока Consumer Electronics
  не мог уйти с «no stock» (та же опечатка), условие `>0.5 && majority active` не выполнялось
  никогда и блок был мёртвым. `zzzz_ef_tr_fix_effects.txt`, который научил здание
  переключаться, и сделал его достижимым — в README компача этот фикс с 23.08 описан как
  сделанный, но сама опечатка компача при этом оставалась в файле.
* **`has_building = building_`** в блоке `building_ecommerce_logistics` — имя просто обрезано,
  и `b:building_ecommerce_logistics` под ним срабатывал в каждом штате без этого здания.
  Порядка четырёх тысяч строк в error.log за сессию, ровно как сообщили.
* **Аудит:** прогнан парсер по всем 168 блокам (self-trigger, несовпадение `has_building` /
  `b:` / `building_type` внутри блока). Кроме этих двух — чисто. Grep по обрезанным именам
  зданий во всех выкладываемых модах — тоже чисто.

**Исправлено:** в шести копиях файла (репо `_tr/ef+tr out fixed`, `__megapacks/megapack`,
`__megapacks/megapack no tgr` + три живых `Documents/…/mod`), md5 сведены.

**Чтобы не потерять при следующей регенерации** — а потеряли бы, файл собирается
`tools/regen_ef_tr_copies.py` из чужого компача — в генератор добавлен `fix_po_stocks()`:
он не патчит две конкретные строки, а пересобирает каждый блок лестницы от его собственного
`b:`-скоупа (имена зданий) и от активируемого метода (триггер обязан называть парный метод,
`pm_no_private_ownership_*` ↔ `pm_private_ownership_majority_*`). Новое здание, добавленное
автором компача в лестницу с такой же опечаткой, будет поймано само. Проверено: запуск
`fix_po_stocks` на до-фиксовой версии файла даёт байт в байт то, что получилось руками,
и печатает ровно две правки.

**Заметки на полях, не сделано:** сборка `megapack` (полная, с T&R) с 25.08 помечена как
неподдерживаемая — а отчёт пришёл именно по ней; замены для набора «TGR + E&F + MR + T&R + PBE»
в каталоге нет. Версии в `.metadata/metadata.json` подняты (`megapack` → `1.13.11-4`,
`megapack no tgr` → `1.13.11-3`, `ef+tr out fixed` → `1.6-fix3`), но **в мастерскую ничего
не заливалось** и **в игре не проверялось**.
